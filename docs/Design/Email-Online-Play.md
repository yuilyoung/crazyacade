# 이메일 회원가입과 온라인 대전

친구 초대방 입장이나 등급 매칭을 누른 사람이 회원가입을 거쳐도 선택한 대전을 이어갈 수 있다. 이메일 확인을 켠 프로젝트에서는 메일을 받은 기기에서 링크를 열고 게임에 비밀번호로 로그인한다.

| 시작한 곳 | 로그인에 성공하면 |
| --- | --- |
| 로비의 로그인·회원가입 | 내 정보에서 닉네임과 전적을 확인한다. |
| 친구 초대방의 입장 버튼 | 선택한 방·인원·맵·아이템·승리 규칙으로 접속한다. 첫 참가자는 대기하고 정원이 차면 서버가 경기를 시작한다. |
| 등급 매칭 | 서버에서 본인 레이팅을 읽고 8인 대기열에 들어간다. |

## 가입에서 입장까지

1. 브라우저는 게임 서버의 `/api/config`에서 Supabase URL과 공개 키를 받아 이메일·비밀번호를 Supabase Auth에 전송한다. 이메일 확인이 필요한 가입은 대기 상태로 표시한다. 확인 전 로그인, 만료된 링크, 재발송 횟수 제한에는 각각 다음에 할 수 있는 동작을 안내한다.
2. 가입·재발송 요청의 `redirect_to`에는 현재 게임 주소와 선택한 공개 대전 설정을 넣는다. 친구+AI에서 직접 고른 팀은 본인의 확인 메일로만 전달한다. 친구에게 공유하는 초대 링크는 방 설정을 보여 주고 입장 버튼을 기다린다.
3. 기본 Supabase 메일 템플릿의 확인 링크는 Auth에서 주소를 검증한 뒤 게임으로 돌려보낸다. 게임은 URL에서 인증 정보를 지우고 비밀번호 로그인을 받는다. 다른 기기에서 메일을 열어도 그 기기에서 선택한 대전을 이어갈 수 있다. 비밀번호를 입력하기 전에 페이지를 새로고침하면 같은 로그인 화면과 입장 설정을 복원한다. 로비로 나가면 대기 중인 입장을 취소한다.
4. 로그인 직후 브라우저는 대기 중인 입장 요청을 한 번 실행한다. 게임 서버는 WebSocket 입장 시 Supabase에서 토큰을 검증하고 계정 ID로 참가 자리를 확보한다. 방에서 상대에게 표시되는 이름은 게임 닉네임이다. 같은 계정으로 연 두 탭은 서로 다른 두 참가자로 집계되지 않는다.
5. 서버가 플레이어의 이동과 승패를 판정한다. 클래식 1대1과 사람만 참가한 정규 4대4는 경기 완료 후 저장 큐와 `record_match`를 거친다. 저장 완료 후 **내 정보 → 최근 경기**에서 해당 계정의 결과를 확인할 수 있다. 친구+AI·릴레이·하모니·파티전은 비랭크 규칙을 따른다.

## 운영 연결

Supabase에서 Email 제공자, 신규 가입, 이메일 주소 확인을 활성화하고 **Site URL**을 주소창에 표시되는 게임의 HTTPS 원본 주소로 설정한다. 운영 게임의 표준 주소는 `https://poppop-arena.onrender.com`이다. 다른 도메인에서도 가입을 받을 경우 해당 게임 주소를 **Redirect URLs**에 등록한다. 확인 메일은 기본 `{{ .ConfirmationURL }}` 링크를 사용하며, 외부 사용자에게 발송할 때는 프로젝트의 SMTP 발신자·수신자 허용 범위와 발송 한도를 확인한다. [Supabase 리디렉션 설정](https://supabase.com/docs/guides/auth/redirect-urls) · [Supabase 메일 템플릿](https://supabase.com/docs/guides/auth/auth-email-templates)

게임 서버에는 같은 프로젝트의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 설정하고 `ALLOW_DEV_GUESTS=false`로 실행한다. 계정 및 경기 저장소는 `Supabase/setup.sql`로 설치한다. 공개 `/health/services`는 인증 설정과 DB·결과 저장 인터페이스를 읽어 점검한다. 실제 발송과 공개 서버의 경기 저장은 확인 메일 수신 및 두 운영 계정의 대전 결과로 판정한다. [Render 활성화 절차](../Operations/Render-Deployment.md#live-이후-회원서비스-활성화)

기존 DB를 개별 마이그레이션으로 관리한다면 `20261121_profile_api_grants.sql`을 적용한다. 첫 입장 시 서버가 프로필을 만들고 경기 후 점수와 승패를 반영하는 데 필요한 권한을 부여한다. 공개 순위표에 필요한 닉네임·레이팅·승·패·무승부·점수는 익명 조회를 허용한다. [마이그레이션](../../Supabase/migrations/20261121_profile_api_grants.sql)
