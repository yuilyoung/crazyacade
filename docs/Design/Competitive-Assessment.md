# 크레이지 아케이드 비교와 다음 개선 평가

평가일: 2026-11-02. 기준 버전: `6ce74072715b38d6a8b86cd77459c9d94b94c525`의 **브라우저 POC**. Unity 빌드의 완성도로 확대 해석하지 않는다.

현재 Pop Pop Arena는 물폭탄·연쇄 반응·아이템·구출·4대4 승패까지 연결된 플레이 가능한 POC다. 크레이지 아케이드와 경쟁할 때 가장 큰 약점은 콘텐츠 숫자보다 첫 경기 진입, 상황 전달, 반복 플레이와 서비스 운영이다. 이번에는 **혼자 즉시 시작하는 비랭크 연습 + 짧은 학습 안내 + 구조·접근성 피드백**을 우선한다.

## 근거와 평가 한계

- 현재 구현 근거: [브라우저 화면](../../Server/public/index.html), [입력·렌더링](../../Server/public/app.js), [서버 경기 처리](../../Server/src/index.js), [맵·외형 카탈로그](../../Server/src/catalog.js), [POC 검증 기록](POC-Acceptance.md), [서비스 준비 상태](../Operations/Service-Readiness.md). 기준 버전에서 확인한 사실이며 이후 변경과 구분한다.
- 원작 참조: [크레이지 아케이드 공식 사이트](https://ca.nexon.com/). 이 문서 작성 중 사이트를 조회하거나 최신 PC 클라이언트를 실행하지 않았다. 원작은 알려진 PC 설치형 버블 대전의 정체성과 장르 경험을 바탕으로 비교한다. 최신 모드 수, 이용자 수, 매출, 동시접속자, 기기 지원, 구체적인 접근성 옵션을 조사한 결과가 아니다.
- 모든 점수는 동일한 기준을 적용한 **전문가 휴리스틱 평가**다. 사용자 조사, 재미 실험, 시장 점유율 또는 개발 완료율이 아니다. 원작의 운영·콘텐츠 점수는 성숙한 PC 게임이라는 참조상을 평가한 값이며 현행 서비스 감사 결과가 아니다.
- 코드와 자동 테스트는 기능 유무·동작을 뒷받침하지만, 재미·호감·잔존율·모바일 편의성을 입증하지 않는다. 소수점은 계산의 재현성을 위한 것이며 그 정밀도로 품질을 측정했다는 뜻이 아니다.

## 고정 평가 기준

각 항목은 0~10점이며 아래 네 하위 기준을 동일 비중으로 평균한다. 종합은 `완성도×0.25 + 재미×0.25 + 독창성×0.20 + 접근성×0.20 + 타깃 적합성×0.10`이다. 이후 평가에서도 가중치와 하위 기준을 유지한다.

척도: 0은 부재, 2는 큰 진입/사용 장애, 5는 기본 경험이 있으나 공백이 큼, 8은 대체로 일관되고 충분한 경험, 10은 해당 사용 목적에서 뚜렷한 공백이 없는 상태다.

| --- | ---: | --- |
| 완성도 | 25% | 핵심 경기의 끝까지 연결 / 콘텐츠와 사용자 흐름 / 오류·상태 경계의 견고함 / 실제 서비스 준비 |
| 재미 | 25% | 설치·회피·연쇄의 순간 판단 / 팀 협력과 구조 / 전략·반복 플레이 변주 / 행동 결과의 피드백 |

독창성은 이름·에셋을 직접 만들었는지뿐 아니라 사용자가 다른 버블 게임 대신 선택할 이유를 포함한다. 원작이 장르 규칙을 최초로 발명했다는 주장은 하지 않는다. 타깃 적합성은 아래에 제안한 사용자 행동을 기준으로 하므로 PC 중심 원작의 전체 시장 가치를 의미하지 않는다.

## 누구를 위한 게임인가

**주 타깃:** 친구와 짧게 한두 판 즐기고 싶은 캐주얼·초보 사용자. 설치 없이 웹에서 시작하고, PC 키보드나 모바일 터치로 참여하며, 친구를 기다릴 때 혼자 연습할 수 있는 경험을 원하는 사람이다. 이들은 현재 팀전·120초 규칙·웹 클라이언트와 가장 직접적으로 연결된다.

**보조 타깃:** 과거 버블 대전 경험이 있고 익숙한 설치·회피·구출을 가볍게 다시 즐기려는 사용자. 익숙함은 진입에 도움이 되겠지만 원작 수준의 타격감·정교한 대전·콘텐츠를 기대할 수 있으므로 단순한 외형 교체만으로 이동할 것이라 가정하지 않는다.

나이·성별만으로 귀여운 그림, 쉬운 난이도 또는 경쟁 선호를 추정하지 않는다. 기존 문서의 “10~20대·어린이·여성”은 검증한 고객 집단이 아니다. 연령보다 기기, 친구 동행 여부, 장르 경험, 세션 길이로 모집하고 실제 관찰로 범위를 좁힌다. 어린이 대상 적합성을 주장하려면 별도의 사용성·운영 검토가 필요하다.

이번 범위는 다음과 같다.

1. **비랭크 연습:** 사람이 한 명 들어오면 봇 7명과 4대4 경기. 매번 서버가 고유한 격리 방을 만들고 다른 인간이 합류하는 공용 대기방과 분리한다. 인증 계정 생성·프로필 쓰기·경기 기록·랭킹 집계 없이 체험할 수 있다. “공개 연습 경로”는 서버 API가 허용한다는 뜻이며 실제 인터넷 배포가 완료됐다는 뜻은 아니다.
2. **짧은 안내와 체크리스트:** 이동 → 설치 → 안전한 곳으로 이동 등 첫 행동을 안내하고 관찰 가능한 진행을 표시한다. 읽었다는 표시만으로 규칙을 이해했다고 간주하지 않는다. 팀 구조 방법과 비랭크 상태를 분명하게 설명한다.
3. **사용자가 켜는 BGM·효과음:** 밝은 자체 8마디 멜로디·코드·베이스·퍼커션으로 대기/대전/결과 장면을 구분하고 설치·폭발·구출 등 행동 결과를 보강한다. 배경음악과 효과음은 독립 음량/켜기·끄기를 제공한다. 기본은 끔이며 음소거 중에도 시각적 정보가 유지된다. 외부 음원이나 원작 사운드를 사용하지 않는다.
4. **움직임 줄이기:** OS 설정과 사용자 설정을 반영해 장식 진동·부드러운 스크롤을 줄인다. 남은 시간과 위험 위치 같은 경기 정보는 유지한다.
5. **색 외 팀 단서와 구조 신호:** 기호·문자 등으로 아군/상대 구분을 보완하고, 버블에 갇힌 아군과 남은 시간을 읽기 쉽게 표시한다. 기존 캔버스 숫자와 신호가 일치해야 한다.

기술 검사로 확인한 범위: 설정 없는 공개 연습 입장, 정확히 사람 1명+봇 7명, 세션 간 방 격리, 일반방 인증 유지, 연습의 인증·프로필·전적·랭킹 쓰기 0건, 이탈 후 정리·재시작, 키보드/터치 입력, 안내 진행, 구조 표시, BGM·효과음의 명시적 켜기·끄기/독립 음량/탭 숨김 정지, 원본 오프라인 WAV 렌더링, OS/수동 움직임 줄이기. 실제 명령과 결과는 [POC 완료 기준](POC-Acceptance.md)에 기록했다. 원격 서비스 운영과 인간 대전의 주관적 재미는 별도 검증이 필요하다.

## 5명 플레이 테스트 계획

이 문서 작성 시 **참여자 0명, 관찰 결과 없음**. 아래 기준은 성공 목표이며 달성 결과가 아니다. 소수 표본으로 시장성·성별 선호·장기 잔존율을 추정하지 않는다.

모집은 버블 장르 초보 3명과 과거 경험자 2명, 모바일 터치와 PC 키보드를 각각 최소 2명이 사용하도록 한다. 행동 집단이 겹쳐도 된다. 같은 안내 문구와 2분 경기 조건으로 1인당 15~20분을 관찰하고 기기·장르 경험·도움 제공 시점을 기록한다. 친구 합류는 참여자끼리 짝을 지어 1대1 초대방으로 별도 확인하며 5명만으로 실제 인간 4대4를 검증했다고 기록하지 않는다.

| 과제·지표 | 측정 방법 | 첫 개선 목표 |
| --- | --- | --- |
| 첫 경기 진입 | 페이지가 조작 가능해진 때부터 실제 이동 가능한 경기 상태까지의 초. 실패·연결 대기는 별도 기록 | 5명 중 4명 이상 무도움 진입, 중앙값 30초 이하 |
| 기본 규칙 학습 | 진행자가 설명하지 않은 상태에서 이동·설치 후 자기 파동 회피를 성공했는지 관찰 | 5명 중 4명 이상 첫 60초 안에 성공 |
| 팀 구분·구조 이해 | 색을 가린 팀 기호 화면에서 아군 식별, 동일 구조 상황을 제시하고 대상·남은 시간 설명 및 구조 시도 관찰 | 5명 중 4명 이상 아군·남은 시간 설명. 구조 성공은 기회 수와 함께 별도 보고 |

| 차별성 | “친구에게 이 게임을 어떻게 소개하겠는가?” 자유 응답 | 답변을 그대로 기록. 유도 없이 반복되는 이유가 있는지 탐색 |

기준 버전과 개선 버전을 모두 비교할 경우 순서 효과를 줄이도록 3명/2명으로 먼저 보는 버전을 나누고, 기준 버전에는 테스트 진행자가 상대 세션을 준비했다는 조건을 명시한다. 자연스러운 혼자 시작 과제에서 기준 버전은 인원 부족으로 실패할 수 있으며 이를 편의상 성공 처리하지 않는다. 5명 결과는 치명적인 진입 문제를 찾는 용도다. 더 많은 사용자·실제 친구 8인 경기·다양한 네트워크에서 반복 확인한 뒤 점수와 우선순위를 갱신한다.
