# Pop Pop Arena 공개 플레이테스트 준비

2026-11-06 기준. 이 문서는 다음 실험의 계획이다. 실제 참가자·공개 운영·광고·입소문·재방문 성과는 미측정이며, 아래 목표는 달성한 실적이 아니다. 자동 검사나 내부 브라우저 실행은 사람의 재미와 인기도를 증명하지 않는다.

## 제품의 한 문장

**“구하고, 패스하고, 다시 한 판 — 별을 이어주는 짧은 팀 배틀.”**

물폭탄 회피와 버블 구조를 익힌 뒤, 별 운반·패스·가로채기를 통해 팀의 다음 행동을 함께 고르는 브라우저 게임. 하모니는 서로 다른 동료에게 패스하고 실제 구조를 더해 한 번의 전달 가치를 바꾼다. 무료 외형은 능력치를 바꾸지 않는다.

첫 대상은 링크로 함께 들어올 수 있는 2–4명의 친구 모임과 짧은 캐주얼 협동 게임을 찾는 사람이다. 처음에는 한국어 안내를 사용하며 모집 지역과 지원 기기는 공개 테스트 전에 명시한다. ‘인기 게임’, 실시간 이용자 수, 검증하지 않은 후기·추천·재미 점수는 사용하지 않는다.

## 준비된 노출면과 경계

- `/about.html`: 제품 소개, 키보드·터치 조작, 훈련→연습→친구 대전, 클래식·릴레이·하모니의 규칙, 초기 POC 상태.
- `/assets/social-preview.svg`: 저장소에서 직접 작성한 1200×630 원본 벡터. Chromium에서 래스터화한 `/assets/social-preview.png`를 메타데이터에 연결한다. 공개 원점에서 플랫폼별 실제 크롤러 확인은 아직 하지 않았다.
- 결과 PNG: 서버가 확정한 자신의 점수·구출·패스·가로채기·별 전달과 자신의 검증된 외형만 표시한다. 닉네임도 생략한다. 계정 UUID, 세션·복귀·접근 토큰, 다른 사람의 이름·기록은 내보내지 않는다.
- 결과 공유는 사용자 클릭으로 기기 공유 창을 열고, 미지원·거부 시 안전한 초대 링크와 내 기록 복사로 이어진다. 취소 시 아무것도 게시하거나 복사하지 않는다. 저장 실패도 복사로 안내하며, 클립보드 거부 시 직접 복사할 수 있는 안전한 링크를 글자로 표시한다.
- 초대 URL은 기존 초대 허용 필드만 다시 구성하고 원래 URL의 인증 query/hash를 버린다. 카드에 초대 URL이나 방 식별자를 그리지 않는다. 비공개 AI 연습 초대를 만들지 않는다.
- 외부 게시, 광고 집행, 이벤트 수집 서버, 자동 추적은 이번 구현에 포함하지 않는다. 브라우저판만 검증 대상으로 삼고 Unity 빌드 검증은 별도 과제다.

공개할 때 배포 원점을 확정하고 `og:image`를 그 원점의 절대 URL로 연결한다. 정적 페이지의 OpenGraph와 Twitter 카드 문구는 초기 POC를 명시한다. 공개 도메인이 없는 현재 단계에서는 임의의 canonical이나 운영 URL을 만들지 않는다.
현재 소개 페이지와 게임 페이지의 상대 이미지 경로는 로컬 준비용이다. 실제 서비스 URL이 정해지면 두 페이지의 `og:image`·`twitter:image`를 절대 URL로 바꾸고, 각 페이지에 절대 `canonical`·`og:url`을 설정한 뒤 크롤러에서 확인한다.

## 다음 실험과 사전 정의 KPI

첫 진행은 동의한 12명(친구 그룹 3개 × 4명)의 20분 관찰 테스트를 목표로 한다. 샘플은 방향을 찾기 위한 소규모 모집이며 통계적 인기 검증이 아니다. 모집하지 못한 경우 실제 n을 그대로 보고한다. 시작 전 기기·게임 경험을 묻고, 첫 세션은 설명 개입 없이 훈련→하모니→자유 재대결 순서로 관찰한다. 도움을 준 시점은 별도 기록한다.

| 질문 | 분자 / 분모와 관찰 방법 | 다음 실험의 판단 목표 |
| --- | --- | --- |
| 혼자 입장하고 시작하는가? | 첫 방문 후 2분 안에 추가 도움 없이 훈련을 시작한 사람 / 첫 방문자 | 80% 이상이면 흐름 유지, 미달이면 입장 화면 수정 |
| 구출을 이해하는가? | 5분 안에 훈련의 실제 구조 단계를 완료한 사람 / 훈련 시작자 | 75% 이상, 실패 원인은 조작·표시·규칙으로 기록 |
| 패스가 작동하고 이해되는가? | 하모니 첫 2판 안에 동료에게 실제 성공 패스를 한 사람 / 하모니 참가자 | 60% 이상, 버튼 인지와 시야 확보를 각각 질문 |
| 협동 규칙을 설명할 수 있는가? | 패스·구출 충전과 분실 초기화를 본인 말로 설명한 사람 / 하모니 참가자 | 70% 이상, 정답 유도 없이 회상 질문 |
| 다음 판을 선택하는가? | 진행자의 요청 없이 첫 경기 후 2분 내 재대결을 누른 사람 / 첫 경기 완료자 | 50% 이상; 말로만 ‘재미있다’는 응답과 구분 |
| 초대로 친구가 실제 들어오는가? | 초대를 받은 뒤 같은 방 입장에 성공한 동의 참가자 / 초대를 받은 동의 참가자 | 80% 이상; 링크 복사 횟수를 가입으로 해석하지 않음 |
| 결과 공유를 쓸 수 있는가? | 요청한 카드 다운로드 또는 직접 공유를 완료한 사람 / 공유 과제를 시도한 사람 | 90% 이상; 공유 창 열림과 외부 게시 완료를 구분 |
| 다시 찾아오는가? | 24–48시간 내 자발적으로 두 번째 세션에 참여한 사람 / 추적에 동의한 첫 세션 완료자 | 탐색 목표 25%; 분모·불참·연락 개입을 함께 표시 |
| 기술적으로 끝까지 가능한가? | 클라이언트 오류·재접속 실패 없이 끝난 경기 / 시작한 경기 | 95% 이상; 기기·브라우저별 n과 원인을 함께 기록 |

재방문은 별도 동의와 테스트용 무작위 연구 코드로 기록한다. 계정 UUID·토큰·상대 닉네임·원본 초대 URL을 연구 노트나 공유 이미지에 저장하지 않는다. 세션 중 성공 패스와 구조는 관찰자 체크와 게임 화면의 실제 기록을 함께 확인한다. 계측 도입은 별도 설계·동의·보관기간 결정 후 진행하며, 현재 구현이 이 KPI를 자동 수집한다고 설명하지 않는다.

결과 보고서는 날짜·실제 n·각 분자/분모·기기 분포·진행자 개입·중도 포기·오류를 포함한다. 사람 수와 경기 수를 섞지 않고, 0분모는 0% 대신 측정 불가로 쓴다. 무료 참가자 모집, 관찰자의 영향, 친구 그룹 편향을 함께 적는다. 첫 결과 전까지 모든 KPI 결과 칸은 **미측정**이다.

## 출시 전 실제 확인할 것

1. 공개 원점에서 로그인·초대·복귀·동시 입장과 개인정보 노출을 확인한다.
2. 390×844 / 844×390 포함 실제 모바일에서 조작과 결과 다운로드·클립보드 거부·기기 공유 취소를 확인한다.
3. 하모니 점수가 실제 패스·구출·전달에서만 바뀌는지, 비랭크 결과가 저장 경로 어디에서도 랭킹에 들어가지 않는지 확인한다.
4. 링크 크롤러의 제목·설명·이미지, 절대 이미지 URL·이미지 MIME·캐시와 접근 가능성을 확인한다.
5. 담당자와 실제 가능한 모집 일정·피드백 창구·중단 안내를 정한 뒤 사람이 모집물을 게시한다. 자동 게시하지 않는다.
