# 벤치마크 06: 조합하고 구하고 이어주는 팀 배틀

평가일: 2026-11-06. 기준은 [벤치마크 05](Benchmark-05-Playability.md)의 브라우저 POC **70/100**이다. 이번 범위는 [경험 확장 설계](../superpowers/specs/2026-11-06-benchmark80-design.md)의 외형·맵·패스·하모니, 조작·화면·설정, 공유·소개와 구조 개선이다.

**상태: 구현·실행·화면을 반영한 독립 설계 평가 — 1차 78.75 → 2차 79.4375 → 최종 80/100.** 구현을 담당하지 않은 AI 평가자가 고정 기준, 소스, 실제 Chromium 화면과 실행 로그를 확인했다. 점수는 독립 AI 평가자의 휴리스틱 설계 판단이며 사용자 조사·개발 완료율·시장성 수치가 아니다. 계획한 기능 수, 목표 80점 또는 테스트 수만으로 점수를 부여하지 않았다. 실제 사용자 참가자는 **0명**이며, 실제 인기·재미·잔존율은 측정하지 않았다.

## 고정 기준과 계산

이 판단에서 패스·가로채기와 수문은 순간 선택, 서로 다른 동료에게 패스한 뒤 구출해 전달 가치를 바꾸는 규칙은 협력과 규칙 차별성의 근거다. 실제 외형과 두 구조 맵, 충전·패스·구출 사건의 시각/문자 전달, 입력 상태·표현 설정의 변화가 각각 관련 항목을 올린다. 입력·화면·음향 수치는 담당자의 초기 실행 결과와 구현을 근거로 한 조건부 판단이며 최종 로그·이미지를 확인해야 한다.

주요 경험 공백은 **새 규칙의 실제 행동 학습**이다. 현재 네 단계 훈련은 기존 폭발·아이템·구출을 가르치지만, 안전하게 패스·충전·분실·기지 전달을 직접 해 보고 같은 상황을 재시도한 뒤 하모니로 이어지는 흐름은 없다. 상황 설명만으로 처음 학습·초보 재시도 점수를 올리지 않는다. 이용 방식 차별성 6은 브라우저 즉시 시작·친구 AI 충원·개인 기여 공유의 조합에 대한 제한적 판단이며, 보편적인 공유나 튜토리얼 기능을 독점적인 혁신으로 보지 않는다. 실제 서비스·기존 짧은 경기 길이·친구 합류도 관련 새 근거 없이 유지한다.

1차 공백을 보완한 별도의 하모니 훈련이 실제 패스→가로채기와 충전 초기화→실제 구출 충전→기지 전달을 판정한다. 1차 당시의 위 공백 설명은 당시 판단 기록이며, 아래 증거가 그중 실조작 학습·이어서 시작하기를 해소한다.

2차 대비 **순간 판단 8→8.5**는 보내기 전에 첫 수신자와 가로채기·막힘을 보고 패스/회피/운반을 선택할 수 있다는 근거다. **정보 가독성·색 외 단서 8.5→9**는 작은 화면에서도 정적 경로·기호·짧은 문장으로 같은 상태를 구분한다는 근거다. 전자는 전술 선택의 정보, 후자는 전달 수단의 식별성으로 구분한다. 새 규칙이나 전략 수가 늘지는 않아 협력·규칙 차별성·전략 변주에는 재가산하지 않았다. 훈련 완료 요약 수정은 기존 학습 점수의 일관성을 확보하며 별도 가산하지 않는다.

## 마케팅 준비와 실제 인기도

소개 페이지·공유 카드·OpenGraph 자산은 배포 후 모집에 사용할 준비물이다. 실제 외부 게시·광고 집행·공개 서비스 이용·유입·설치·활성 이용자·재방문 자료는 없다. **현재 인기도는 미측정**이며 인기 수치·리뷰·시장 점유율을 만들지 않는다. 공유 버튼을 자동 실행한 횟수는 실제 사용자의 공유 의사나 추천율이 아니다.

기존 5명 관찰 계획은 초보의 진입·학습 문제를 찾는 과제다. 이번 [공개 플레이테스트 준비](Launch-Playtest.md)는 후속 협동 관찰의 목표를 친구 그룹 3개×4명, 총 12명으로 정한다. 두 문서의 모집 규모는 실제 참가자 수가 아니다. 공개 테스트가 가능해지면 모집 유입→첫 경기→초대 합류→자발적 재경기와 24–48시간 내 재방문을 각각 분모·기간과 함께 기록한다. 소규모 관찰 결과로 시장성을 일반화하지 않는다.

## 객체지향·MVVM의 평가 범위

읽은 소스에서 `ArenaViewModel`은 서버 스냅샷을 복제·재귀 동결하고 표시 상태와 명령 가능 여부를 만든다. DOM·Canvas·WebSocket을 직접 생성하지 않으며, 주입한 전송 포트로 허용된 명령을 보낸다. 실제 `app.js`가 이를 구독해 사용하므로 연결되지 않은 샘플 클래스는 아니다. `input-controller.js`의 물리 키 상태와 별도 80ms 입력 타이머는 렌더 프레임과 분리되며, `arena-renderer.js`와 `socket-transport.js`도 실제 조립 경로에 연결된다.

서버에는 공통 `initialize/step/result/snapshot` 규칙 계약, 중립 위험 예측, 경기 실행 경계와 공통 랭크 정책이 생겼다. 이는 합성과 계약을 이용한 모듈 분리다. 깊은 상속·가상 메서드를 추가하지 않은 사실은 결함으로 점수화하지 않는다. 반면 DOM 표시의 일부와 세션 조정은 여전히 `app.js`에 있고, 서버 Room/Player는 공유 가변 데이터이며 경기 엔진도 플레이어 socket 상태를 참조한다. 완전한 MVVM·도메인 캡슐화·전송 독립으로 판정하지 않는다. Unity 구조는 이번 브라우저 개선과 별도로 남는다.

구조는 고정 20개 기준 밖의 21번째 항목을 만들지 않는다. 경계 개선과 실제 회귀 증거가 뒷받침하는 견고함만 기존 기준에서 판단하며, 파일 분리 자체를 재미·독창성·마케팅 점수로 환산하지 않는다.

## 남은 검증과 개선

설계 점수 80은 실제 사용자 재미나 인기, 운영 완료를 뜻하지 않는다. 전체 훈련 180초는 설명을 읽는 동안에도 흐른다. 예상 패스는 마지막 공개 상태를 보여 주므로 움직이는 상대·수신자에 대한 실행 결과를 보장하지 않으며, 밀집한 인간 경기에서 안내가 위험 위치를 가리는지도 관찰해야 한다. 실제 서비스·Unity·사람의 학습 전이/밸런스·실기기·인기도는 계속 미검증이다.

다음 우선순위는 실제 초보의 두 훈련 무도움 완료와 일반 경기로의 전이, 친구 그룹의 자발적 패스/구출·재대결, 실제 모바일의 안내 가림·입력 오류, 공개 서비스의 인증·초대·복귀다. 관찰에서 문제가 확인되면 같은 20개 기준으로 점수를 유지하거나 내린다. 마케팅 준비물과 테스트 통과를 실제 유입·추천·재방문 성과로 바꾸어 기록하지 않는다.
