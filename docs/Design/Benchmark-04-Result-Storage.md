# 벤치마크 04: 경기 결과 저장 복구

평가일: 2026-11-03. 기준 버전은 `79008a6`의 **브라우저 POC**다. [벤치마크03](Benchmark-03-Reconnect.md)의30초 자리 복귀·새로고침 복구까지 포함한다. 이번 증분은 [결과 저장 복구 설계](../superpowers/specs/2026-11-03-result-outbox-design.md)의 완료 결과 파일 보관·동일ID 재전송·실제 저장 상태 표시다. 진행 중 경기의 서버 재시작 복원이나 공개 서비스 구축으로 확대하지 않는다.

**상태: 구현·기술 검증을 반영한 설계 재평가.** 아래 실행 근거를 확인해 완료 결과 저장의 견고함과 서비스 준비 항목을 평가했다. 실제 사용자 플레이 테스트는0명이며 자동 검사로 재미·만족도·잔존율을 입증하지 않는다.

## 같은 기준 유지

[기존 비교 평가](Competitive-Assessment.md)의 다섯 항목, 가중치, 네 하위 기준과0~10 척도를 유지한다. 항목 점수는 네 하위 점수의 단순 평균이다. 가중 종합은 `완성도×0.25 + 재미×0.25 + 독창성×0.20 + 접근성×0.20 + 타깃 적합성×0.10`이다.0은 부재,2는 큰 사용 장애,5는 기본 경험과 큰 공백,8은 대체로 일관되고 충분한 경험,10은 해당 목적에서 뚜렷한 공백이 없는 상태다. 소수점은 계산 재현을 위한 것이며 실측 정밀도를 뜻하지 않는다.

| 항목 | 비중 | 하위 기준 순서 |
| --- | ---: | --- |
| 완성도 | 25% | 핵심 경기의 끝까지 연결 / 콘텐츠와 사용자 흐름 / 오류·상태 경계의 견고함 / 실제 서비스 준비 |
| 재미 | 25% | 설치·회피·연쇄의 순간 판단 / 팀 협력과 구조 / 전략·반복 플레이 변주 / 행동 결과의 피드백 |
| 독창성 | 20% | 독자 시각·캐릭터 정체성 / 규칙의 차별성 / 기억할 수 있는 제품 약속 / 이용 방식의 차별성 |
| 접근성 | 20% | 처음 경기 시작·학습 / 입력 수단 / 정보 가독성·색 외 단서 / 움직임·소리 조절 |
| 타깃 적합성 | 10% | 짧은 세션 / 친구와 함께하기 / 초보자가 연습·실패 후 다시 하기 / 웹·모바일 사용 맥락 |

최신 원작 클라이언트나 운영 상태를 이번에 조사하지 않았다. 기존 문서의 크레이지 아케이드 참조 종합7.4375/10을 유지하며 현행 원작의 실측 점수라고 해석하지 않는다.

## 사용자와 운영 흐름의 변화

운영 클래식 경기가 종료되면 점수판에 저장 상태가 나타난다. 서버가 완료 결과를 먼저 파일에 기록하고 Supabase로 전송한다. 일시 오류에는 자동 재시도하고 DB 성공 응답을 받은 뒤 저장 완료를 표시한다. 저장 지연이나 실패가 새 라운드를 막지는 않으며, 이전 경기의 늦은 응답으로 현재 경기의 저장 상태를 바꾸지 않는다. 개발 임시 랭킹과 비랭크 경기는 그 차이를 표시한다.

같은 matchId와 같은 payload로 재전송하므로 DB가 이미 처리한 요청의 응답이 유실되어도 결과를 중복 집계하지 않는다. 영속 디스크를 유지하면 프로세스 재시작 뒤 미전송 완료 결과를 다시 처리한다. 진행 중 룸·캐릭터·복귀 토큰은 메모리에 있으므로 서버 재시작으로 사라진 경기를 재개할 수는 없다.

큐는 한 프로세스 소유의 `RESULT_OUTBOX_DIR`에 있으며 최대1000개·레코드당32KiB다. 전송은 최대2건, HTTP 제한 시간5초, 일시 오류 재시도 간격은1/2/5/10/30초 이후30초다. 영구 오류로 보관된 파일은 원인 수정 후 재시작하면 다시 시도한다. 손상 파일은 삭제하지 않고 invalid로 집계한다. 파일·공개 상태·로그에는 토큰/서비스 키/오류 응답 본문을 넣지 않는다. 운영 시 `/app/data` 영속 볼륨과 별도 백업·관측 설정이 필요하다.

## 다음 사용자 검증과 서비스 공백

**실제 참가자0명, 관찰 결과 없음.** 다음 비공개8인 테스트에서는 기존 게임 밸런스와 복귀 이해도에 더해 저장 지연 문구가 실패로 오해되는지, 저장 완료와 임시/비랭크를 구분하는지, 새 라운드 중 이전 결과 확인이 필요한지 관찰한다. 자동화된 재시도 성공률을 사람의 신뢰나 만족도로 치환하지 않는다.

다음 운영 검증은 실제 Supabase와 공개 HTTPS/WSS 호스트 연결, 영속 볼륨 교체/백업 복원, 저장 큐 포화와 장애 알림, 실제 친구8명의 다기기 플레이다. 계정 장기 연결·진행 경기 재시작 복원·다중 인스턴스 큐/룸 라우팅은 별도 범위다. 근거가 부족하거나 실제 문제가 확인되면 같은 기준의 점수를 유지하거나 낮춘다.
