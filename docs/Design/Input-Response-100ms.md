# 키보드 입력 응답 100ms 개선

## 2026-11-25 조작 검증 방법

Chromium에서 두 참가자가 실제 대전에 입장해 방향키와 WASD로 같은 시작 지점의 두 통로를 걷는다. 각 네트워크 조건마다 짧은 입력 24회, 길게 걷기 5회, 반전 11회, 직각 회전 6회를 검사한다. 키를 누른 때부터 전송까지의 시간, 내 캐릭터의 표식이 요청 방향으로 이전 프레임 대비 0.5 CSS 픽셀 이상 움직일 때까지의 시간, 서버가 해당 방향으로 이동을 확정할 때까지의 시간을 따로 측정한다.

기준 버전은 `c08a94f`다. 로컬과 WebSocket 송수신에 각각 40ms를 더한 조건에 동일한 경로를 적용한다. 두 조건 모두 전송과 화면 반응의 **최댓값이 각각 100ms 이하**여야 한다. 길게 누르는 동안 첫 이동과 마지막 이동 사이에 표식이 0.1 CSS 픽셀 이상 움직인 프레임들의 간격을 측정한다. 각 조건에서 이 간격의 **95백분위수가 50ms 이하**여야 한다. 서버 판정은 기존 100ms 틱과 캐릭터 이동 쿨다운을 따르며, Canvas 시간은 브라우저가 그리기 명령을 제출한 시점까지다.

시간 단위는 ms다. 기준 버전은 편도 40ms 조건에서 화면 반응이 7회 예산을 초과했다. 조작 개편 커밋 `c241efa`는 동일한 코드로 두 차례 실행해 184회 모두 100ms 이내였다. 실제 디스플레이 표시, 물리 키보드 지연, 일반 인터넷의 지터·손실은 이 실험의 측정 범위 밖이다. 모션 줄이기 또는 효과 간소화를 선택하면 서버 좌표를 직접 표시한다. [조건별 분포와 소스 해시](evidence/input-response/controls-2026-11-25.json)

반전할 때 캐릭터는 서버에서 이미 확인한 위치를 기준으로 다음 한 칸을 그린다. 서버의 다음 이동 가능 시각까지 남은 시간에 맞춰 짧은 반전 동작을 이어서, 모서리를 먼저 돌아간 뒤 제자리에 멈추던 구간을 줄였다. 고정 지형은 다시 그려야 할 때만 갱신한다. 같은 팝 가든 팀전 프레임에서 매번 바닥 195칸과 벽·상자 88개를 그리던 작업이 배경 합성 1회로 줄었다.

### 키보드와 터치 사용성

데스크톱 대전 버튼에 현재 지정한 키를 표시하고, 누르고 있는 방향에 색을 채운다. 이동을 IJKL, 물폭탄을 Q로 바꾼 뒤 화면과 접근성 단축키가 함께 바뀌는지 확인했다. Escape를 길게 눌러도 설정은 한 번만 열리고, 닫으면 키보드 포커스가 경기장으로 돌아온다. 물폭탄 버튼의 작은 글자 대비는 2.90:1에서 5.71:1로 높였다. [변경한 키로 오른쪽 이동 중인 대전 화면](evidence/input-response/desktop-remapped-held.png)

모바일에서는 한 손가락으로 방향을 밀어 바꾸면서 다른 손가락으로 물폭탄을 놓을 수 있다. 방향 패드 밖으로 밀면 반복 이동이 멈추고 다시 안으로 밀면 재개된다. Chromium 터치 에뮬레이션에서 왼손 배치·글자 크기 130%로 확인한 최소 조작 영역은 세로 390×844에서 46px, 가로 844×390에서 44px였다. [왼손 배치를 사용한 가로 대전 화면](evidence/input-response/mobile-844x390-lefthand-130.png)

첫 CI 실행에서는 설정창을 닫은 직후의 벽 충돌 검사가 실패했다. 브라우저가 뒤늦게 보낸 `close` 이벤트가 경기장 포커스를 설정 버튼으로 되돌려 첫 방향키가 빠졌다. 후속 수정은 설정을 닫는 시점에 입력을 복구한다. 회귀 검사는 닫기 직후 경기장에 전달한 첫 방향키와 서버의 벽 충돌 횟수 증가를 함께 확인한다. [실패를 재현한 CI 실행](https://github.com/yuilyoung/crazyacade/actions/runs/45623158140)

## 이전 입력 예측 도입 기록

사용자 요청: 스케줄러보다 게임 기능 개선을 먼저 수행한다. 입력 후 화면 이동 시작까지 100ms 이하를 실제 브라우저에서 측정한다. 기존99.73 점수는 입력 응답이나 사람의 자연스러움 평가가 아니며 이번 요구의 증거로 사용하지 않는다.

원인: 키 입력은 즉시 전송되지만 표현 타임라인은100ms 서버 틱에서 이동을 확정한 뒤에야 시작한다. 반복 입력은80ms 간격이다. 서버 판정과 표현을 분리해 내 캐릭터만 로컬의 안전한 한 칸을 먼저 표시한다. 서버의 좌표·충돌·아이템·폭탄·승패는 변경하지 않는다.

구현: 별도 local-movement 모듈에서 한 칸 예측, 확정 응답과의 연속 연결, 거절/새 장애물/300ms 수신 공백 시 복구, 코너 보존, 재접속·장면·설정·포커스 변경 초기화를 담당한다. renderer는 내 캐릭터 포즈에만 적용한다. 줄인 모션/최소 효과는 기존 서버 확정 위치를 유지한다. 입력 전송 빈도를 높여 서버의 제한을 우회하지 않는다.

검증: 실패하는 회귀 테스트를 먼저 작성한다. 실제 키 입력→WebSocket 전송→서버 확정→Canvas의 내 표식 위치 변화 시간을 각각 관찰한다.20회 이상 측정해p50/p95/최대를 보고한다. 길게 누름·방향 전환·벽·거절·스테일·갇힘·모달 회귀를 포함한다. 로컬/시험 네트워크 수치와 운영망의 미검증 한계를 구분한다. 기존 전체 테스트와 게임 기능 브라우저 검사를 유지한다.


## 사용자 평가와 점수의 구분

사용자는 넥슨 크레이지 아케이드 대비 현재 서비스가50점 미만이라고 평가했다. 이 평가는 존중하며 이전 합성 이동 점수로 반박하지 않는다. 품질 게이트의90/100은 명시한 자동 검사 통과 기준이며 원작 대비 미술·재미·조작감90점이 아니다. 사람의 플레이 비교 평가는 미검증이다.

## 변경 사항

내 캐릭터의 입력 반응만 예측하며 최대 한 칸의 미확정 이동을 표시한다. 실제 판정·아이템·폭발·승패는 서버가 소유한다. 확인 응답에서 같은 이동을 두 번 재생하지 않는다. 반환·방향 교체·조기 확정·수신 공백·장면 변경·갇힘·죽음·포커스와 모션 설정에 대한 회귀 검사를 추가했다. 직각 경로의 남은 코너를 유지하며 재접속 시 과거 예측을 지운다.

물줄기 아이템을 실제로 주운 뒤 설치한 물폭탄의 서버range가3→4로 증가하는 wire 검사를 추가했다. 물폭탄 몸체는 능력치에 따라 최대8% 커지고, 퓨즈 표시와 별도로 실제 범위 숫자가 보인다. 효과·스킨·고대비·모션 줄이기의 기존 의미를 유지한다.

## 품질 게이트와 남은 네트워크 조건

전체 명령은 `python3 scripts/check-quality-gates.py --all`이다. 10영역×10점, 최소90점과 필수 검사 조건을 모두 만족해야 통과한다. 부족한 결과를 건너뛰거나 과거 결과로 점수를 채우지 않는다.

현재 클라우드의 허용 도메인에 없는 `cdn.playwright.dev`, `playwright.download.prss.microsoft.com`에서 Firefox/WebKit 설치가403으로 거부되었다. 필요한 도메인을 환경 설정 초안에 추가했다. GitHub CI 확인에 필요한 `api.github.com`도 추가했다. 초안 저장은 현재 네트워크 적용·배포를 뜻하지 않는다. 3엔진 검사가 실제 통과하기 전에는 전체 게이트를 통과했다고 표시하지 않는다.

[표본·소스 해시](evidence/input-response/input-latency.json)를 보관한다. 서버 확정은 로컬 최대169.2ms로 화면 예측과 구분하며 서버가100ms 이내에 항상 판정한다고 주장하지 않는다. 이 표본은 실제 인터넷 전체나 물리 디스플레이 지연을 보장하지 않는다. 한 칸 예측의 확인 대기 때문에 방향 반전 중 일시적인 이동 간격이 남을 수 있으며, 최초 반응 시간 개선을 전체 애니메이션의 완전한 매끄러움으로 확대하지 않는다.

Node696개, 타임라인/로컬 표현45개 관련 검사,3D가 아닌 Canvas 실제 UI, 실제 아이템 range3→4, 전체 게임/회원 E2E와64접속/8룸/60초 부하가 통과했다. 독립 검토에서 발견한 반환/코너/확정 타이밍 문제는 회귀 검사로 고쳤다. 추가 무작위1000경로·100만 표본 검토에서 대각선 이동과 최종 권위 위치 불일치는 발견되지 않았다.

전체 게이트의 로컬 점수는 **92.5/100**이나 **필수 브라우저 검사가 실패하여 합격이 아니다**. Chromium 새로고침/재개는 통과했지만 Firefox/WebKit 설치 차단으로 전체3엔진 검사는 실패했다. [현재 게이트 보고서](evidence/input-response/quality-report.json). CI는3엔진을 설치해 같은 검사를 실행하며 실패하면 통과 처리하지 않는다.
