# 벤치마크 03: 끊겨도 같은 경기로 돌아오기

평가일: 2026-11-02. 기준 버전은 `ab6fdd7`의 **브라우저 POC**이며, [벤치마크02](Benchmark-02-Relay-Social.md)의 팝 릴레이·초대 링크·동일방 재대결까지 포함한다. 이번 증분은 [연결 복구 설계](../superpowers/specs/2026-11-02-reconnect-design.md)의 일시 단절·같은 탭 새로고침·자리 복귀다. Unity와 공개 서비스의 완성도로 확대하지 않는다.

**상태: 구현·기술 검증을 반영한 설계 재평가.** 아래 실행 근거를 확인해 일시 단절 복구의 견고함과 웹 사용 흐름을 평가했다. 실제 사용자 플레이 테스트는 0명이다. 자동 검사만으로 재미·만족도·장기 잔존율을 입증하지 않는다.

## 평가 기준 유지

[기존 비교 평가](Competitive-Assessment.md)의 다섯 항목, 가중치, 네 하위 기준 순서와 0~10 척도를 유지한다. 항목 점수는 네 하위 점수의 단순 평균이고 가중 종합은 `완성도×0.25 + 재미×0.25 + 독창성×0.20 + 접근성×0.20 + 타깃 적합성×0.10`이다. 0은 부재, 2는 큰 사용 장애, 5는 기본 경험과 큰 공백, 8은 대체로 일관되고 충분한 경험, 10은 해당 목적에서 뚜렷한 공백이 없는 상태다. 계산 소수점은 측정 정밀도를 뜻하지 않는다.

| 항목 | 비중 | 하위 기준 순서 |
| --- | ---: | --- |
| 완성도 | 25% | 핵심 경기의 끝까지 연결 / 콘텐츠와 사용자 흐름 / 오류·상태 경계의 견고함 / 실제 서비스 준비 |
| 재미 | 25% | 설치·회피·연쇄의 순간 판단 / 팀 협력과 구조 / 전략·반복 플레이 변주 / 행동 결과의 피드백 |
| 독창성 | 20% | 독자 시각·캐릭터 정체성 / 규칙의 차별성 / 기억할 수 있는 제품 약속 / 이용 방식의 차별성 |
| 접근성 | 20% | 처음 경기 시작·학습 / 입력 수단 / 정보 가독성·색 외 단서 / 움직임·소리 조절 |
| 타깃 적합성 | 10% | 짧은 세션 / 친구와 함께하기 / 초보자가 연습·실패 후 다시 하기 / 웹·모바일 사용 맥락 |

원작의 최신 클라이언트를 이번에 실행하거나 운영 상태를 조사하지 않았다. 이전 문서의 원작 참조 종합 `7.4375/10`은 그대로 두며 현행 크레이지 아케이드의 실측 점수로 취급하지 않는다.

## 전후 점수와 근거

| 항목 | `ab6fdd7` 하위 점수 | 이전 점수 | 이번 잠정 하위 점수 | 이번 잠정 점수 |
| --- | --- | ---: | --- | ---: |
| 완성도 | 8 / 7 / 6 / 3 | 6.00 | 8 / 7 / 7 / 3.5 | 6.375 |
| 재미 | 7 / 8 / 7 / 6.5 | 7.125 | 7 / 8 / 7 / 6.5 | 7.125 |
| 독창성 | 6 / 5.5 / 6.5 / 5 | 5.75 | 6 / 5.5 / 6.5 / 5 | 5.75 |
| 접근성 | 7 / 7 / 6.5 / 5 | 6.375 | 7 / 7 / 6.5 / 5 | 6.375 |
| 타깃 적합성 | 8 / 7.5 / 7.5 / 7 | 7.50 | 8 / 7.5 / 7.5 / 7.5 | 7.625 |
| **가중 종합 / 10** | **1.5 + 1.78125 + 1.15 + 1.275 + 0.75** | **6.45625** | **1.59375 + 1.78125 + 1.15 + 1.275 + 0.7625** | **6.5625** |

100점 환산 잠정 변화는 **64.5625 → 65.625**, 반올림하면 **64.6 → 65.6점**이다. +1.0625점의 근거는 아래 세 하위 항목에 한정한다. 목표 숫자에 맞춘 상향이 아니며 개발 완료율 65.6%나 실제 이용자 만족도라고 해석하지 않는다.

| 바뀐 기준 | 변화가 인정되는 근거 | 상승의 제한 |
| --- | --- | --- |
| 오류·상태 경계의 견고함 6→7 | 유효한 복귀가 같은 참가자/경기/전투 상태를 유지하고 잘못된 토큰·다른 계정·만료·이전 소켓 경합을 거부함을 실제 WebSocket 검사로 확인. 대기·경기·종료방과 연습·릴레이·재대결 수명 검증 | 복귀 유예 중에도 경기가 계속되므로 실패를 모두 없애지 않음. 서버 재시작·다중 인스턴스·저장 실패 재시도·장시간 부하 공백은 유지 |
| 실제 서비스 준비 3→3.5 | heartbeat, 제한된 복귀 시간, 명시적 이탈과 계정 재검증의 경계를 확인. 저장소 차단 시에도 같은 익명 계정을 유지하는 실제 브라우저 검사 통과 | 실제 Supabase·공개 TLS/호스트·관측·운영 부하를 검증하지 않았으므로 소폭만 반영. 로컬 인증 fixture를 실제 서비스 검증으로 대체하지 않음 |
| 웹·모바일 사용 맥락 7→7.5 | 실제 Chromium에서 단절/새로고침 뒤 기존 참가자로 복귀하고 모바일390×844 화면에 연결 상태·나가기·조작이 유지됨을 확인 | 실제 모바일 기기·백그라운드 제한·이동통신/Wi-Fi 전환은 미검증. 30초 초과나 서버 재시작 뒤에는 새로 입장해야 함 |

재접속은 흔한 서비스 기능이며 고유한 게임 규칙이 아니므로 독창성 점수를 올리지 않는다. 전투 규칙·전략·시각/청각 피드백·입력 수단이 확장되지 않아 재미와 접근성도 유지한다. 함께하기·초보 재시도는 이미 초대/재대결/연습을 반영한 점수이므로 같은 편익을 중복 가산하지 않는다.

## 사용자에게 달라지는 흐름

브라우저가 예상치 못하게 끊기면 입력을 비우고 남은 복귀 시간을 보여 준다. 같은 탭에서 새로고침해도 탭별 복귀 정보를 이용한다. 서버가 같은 참가자의 자리·팀·스킨·능력치·점수·경기 ID를 30초 보존하고, 인증 입장자는 현재 JWT로 같은 계정인지 다시 검증한다. 유효한 복귀 뒤 최신 권위 상태를 받은 다음 조작을 재개한다.

그동안 경기는 멈추지 않고 캐릭터도 공격을 받는다. 릴레이 별은 떨어지고 오프라인 상태에서 재획득하지 않는다. 복귀가 추가 무적이나 아이템·생명 초기화를 주지 않는다. 대기방/재대결은 복귀 대기 참가자를 포함해 전원이 연결되어야 진행한다. 명시적 나가기는 바로 자리를 반납하며, 서버에 닿지 않는 상태에서 나가면 유예 만료 때 정리한다. 유예 만료·권한 실패·다른 소켓에서의 복귀는 안내 후 로비로 돌아간다.

복귀 정보는 비공개 토큰이며 초대 링크·공개 state·로그에 포함하지 않는다. 서버 프로세스 메모리에 남아 있는 경기로만 복귀한다. 장기 계정 보존, 서버 장애 복원, 기기간 계정 이동을 해결하는 기능은 아니다. Unity와 opt-in하지 않은 클라이언트의 기존 즉시 이탈 동작은 유지한다.

## 다음 사용자 검증과 서비스 공백

**실제 참가자 0명, 관찰 결과 없음.** 자동화 브라우저의 성공률은 사람의 복귀 이해도나 모바일 만족도가 아니다. 다음 비공개 8인 플레이 테스트에서 기존 클래식/릴레이 밸런스 항목과 함께 아래를 관찰한다.

| 확인할 문제 | 관찰할 사실 |
| --- | --- |
| 끊김 중 경기가 계속되는 규칙을 이해하는가 | 복귀 안내를 읽은 뒤 캐릭터가 공격받을 수 있음을 설명하는지, 복귀 후 탈락 상태를 버그로 오해하는지 |
| 기다리는 팀원이 상태를 이해하는가 | 명단의 복귀 대기/남은 시간 인지, 준비를 누른 뒤 진행되지 않는 이유 설명, 불필요한 나가기/재입장 |
| 실제 기기에서 복귀가 유용한가 | 기기·브라우저·망 전환·백그라운드 시간별 복귀 소요 시간/실패 원인/30초 초과 빈도, 조작 재개 후 입력 오류 |
| 새로고침과 나가기 구분이 자연스러운가 | 기대한 계정/캐릭터 복귀 여부, 명시적 이탈 후 자동 복귀가 없는지, 저장소 제한 상황의 안내 이해 |

다음 우선순위는 실제 Supabase와 공개 HTTPS/WSS 호스트 연결, 오류/저장 실패 관측, 인간 4대4 밸런스 검증이다. 서버 재시작·다중 인스턴스 복구와 Unity 클라이언트 확장은 각각 별도 설계·검증이 필요하다. 검증 근거가 부족하거나 사용자 문제가 확인되면 같은 기준에서 점수를 유지하거나 낮춘다.
