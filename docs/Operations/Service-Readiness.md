# 서비스 준비 상태 (2026-11-02)

브라우저 4대4 핵심 플레이와 아이템·점수·랭킹·블록 스킨에 이어 비랭크 AI 연습·행동 안내·선택형 BGM/효과음·구조 표시, 팝 릴레이·초대 링크·동일방 재대결을 구현했다. 이번 증분은 브라우저의 일시 단절과 새로고침 복귀다. 최종 검증 기록은 [POC 완료 기준](../Design/POC-Acceptance.md)과 [벤치마크03](../Design/Benchmark-03-Reconnect.md)의 상태를 따른다. 아래는 기능/검증 기준이며 임의의 완성도 백분율은 아니다.

| 영역 | 구현 및 검증 | 남은 서비스 작업 |
| --- | --- | --- |
| 전투 | 8인 팀전, 선택·스킨·맵, 물폭탄·구출, 아이템전 ON/OFF, 다트·속도·파동 강화 | 실제 사용자 다기기 지연/장시간 테스트, 봇/인간 대전 밸런스 조정 |
| 화면 | 테마별 블록 SVG 6종, 모바일 조작, 점수판·등급·랭킹 | 실사용자 안내/음향 평가, Unity 신규 UI 확장 |
| 계정·저장 | JWT 검증·서버 전용 집계, PostgreSQL 트랜잭션·권한 검사 | 실제 Supabase에 마이그레이션 및 익명 로그인 설정, 장기 계정 연결 |
| 연결 복구 | 브라우저 opt-in, 30초 자리 보존, 비공개 복귀 토큰·동일 계정 재검증, 명시적 이탈과 heartbeat | 실제 이동통신/Wi-Fi 전환, Unity 지원, 서버 재시작·다중 인스턴스 복구 |
| 배포 | 비루트 Docker 이미지, 상태 검사, CI·GHCR 게시 워크플로 | 배포 호스트·도메인·TLS·운영 환경변수 설정, 백업·관측·부하검사 |
| 협업 자동화 | 개발/Review/Fix 역할 정의, 격리 검증 후 draft PR | API secret·활성화 변수·PR 권한 설정 후 실제 실행 확인 |

현재 서버는 한 프로세스 메모리에 룸과 복귀 권한을 보관한다. 브라우저 재접속은 같은 프로세스에서 30초 유예 안에 돌아오는 경우를 대상으로 한다. 자동 매칭, 다중 서버 룸 라우팅, 프로세스 재시작 복원, 저장 실패 재시도 큐는 없다. 결과 저장 실패는 서버 로그에 남기며, 경기 종료 화면만으로 영구 저장 성공을 보장하지 않는다.

검증 명령과 범위는 [POC 완료 기준](../Design/POC-Acceptance.md), 활성화 설정은 [GitHub 자동화 안내](GitHub-Automation.md), Supabase 설정은 [README](../../README.md)를 따른다. 실제 Supabase, 원격 Actions, GHCR 게시, 공개 배포 성공을 로컬 검증으로 대신하지 않는다.

비랭크 연습은 계정 없이 허용하는 별도 경로이며 사람 대전 인증 우회 기능이 아니다. 운영 환경에도 프로세스당 연습방 8개 제한과 연결 정리가 적용된다. 복귀 유예 중인 연습방도 정원에 포함되고 명시적 이탈이나 유예 만료 때 정리된다. 공개 대규모 트래픽을 위한 요청/연결 비율 제한 및 관측은 별도 운영 과제다.

팝 릴레이는 인증된 사람 대전도 비랭크이며 기존 클래식 레이팅과 분리된다. 연결이 끊긴 운반자는 별을 떨어뜨리고 복귀 대기 중 다시 획득하지 않는다. 경기는 계속되며 연결 복구가 피격·탈락을 취소하거나 추가 무적을 주지 않는다. 같은 방 재대결은 별도 기능이며 복귀 유예 중인 참가자도 기다린다.

복귀 토큰은 참가자에게만 보내고 브라우저의 탭별 `sessionStorage`에 보관한다. 초대 링크·공개 state·로그에 포함하지 않는다. 인증 입장자는 복귀 때 유효한 JWT와 동일 사용자 검증이 필요하다. 토큰을 가진 새 연결이 복귀하면 이전 소켓을 교체하며 이전 연결은 입력을 보낼 수 없다. Unity와 opt-in하지 않은 구형 클라이언트는 기존 즉시 이탈 동작을 유지한다. 이 경계는 로컬 인증 fixture 검사 대상이며 실제 Supabase 검증을 대신하지 않는다.
