# 서비스 준비 상태 (2026-11-02)

브라우저 4대4 핵심 플레이와 아이템·점수·랭킹·블록 스킨에 이어 비랭크 AI 연습·행동 안내·선택형 BGM/효과음·구조 표시, 팝 릴레이·초대 링크·동일방 재대결을 구현했다. 최종 검증 기록은 POC 완료 기준을 따른다. 아래는 확인 가능한 기능/검증 기준이며 임의의 완성도 백분율은 아니다.

| 영역 | 구현 및 검증 | 남은 서비스 작업 |
| --- | --- | --- |
| 전투 | 8인 팀전, 선택·스킨·맵, 물폭탄·구출, 아이템전 ON/OFF, 다트·속도·파동 강화 | 실제 사용자 다기기 지연/장시간 테스트, 봇/인간 대전 밸런스 조정 |
| 화면 | 테마별 블록 SVG 6종, 모바일 조작, 점수판·등급·랭킹 | 실사용자 안내/음향 평가, Unity 신규 UI 확장 |
| 계정·저장 | JWT 검증·서버 전용 집계, PostgreSQL 트랜잭션·권한 검사 | 실제 Supabase에 마이그레이션 및 익명 로그인 설정, 장기 계정 연결 |
| 배포 | 비루트 Docker 이미지, 상태 검사, CI·GHCR 게시 워크플로 | 배포 호스트·도메인·TLS·운영 환경변수 설정, 백업·관측·부하검사 |
| 협업 자동화 | 개발/Review/Fix 역할 정의, 격리 검증 후 draft PR | API secret·활성화 변수·PR 권한 설정 후 실제 실행 확인 |

현재 서버는 한 프로세스 메모리에 룸을 보관한다. 자동 매칭, 재접속, 다중 서버 룸 라우팅, 저장 실패 재시도 큐는 없다. 결과 저장 실패는 서버 로그에 남기며, 경기 종료 화면만으로 영구 저장 성공을 보장하지 않는다.

검증 명령과 범위는 [POC 완료 기준](../Design/POC-Acceptance.md), 활성화 설정은 [GitHub 자동화 안내](GitHub-Automation.md), Supabase 설정은 [README](../../README.md)를 따른다. 실제 Supabase, 원격 Actions, GHCR 게시, 공개 배포 성공을 로컬 검증으로 대신하지 않는다.

비랭크 연습은 계정 없이 허용하는 별도 경로이며 사람 대전 인증 우회 기능이 아니다. 운영 환경에도 프로세스당 연습방 8개 제한과 연결 정리가 적용된다. 공개 대규모 트래픽을 위한 요청/연결 비율 제한 및 관측은 별도 운영 과제다.

팝 릴레이는 인증된 사람 대전도 비랭크이며 기존 클래식 레이팅과 분리된다. 같은 방 재대결은 연결을 유지하는 기능으로, 네트워크가 끊긴 사용자의 재접속·자리 복구는 여전히 별도 과제다.
