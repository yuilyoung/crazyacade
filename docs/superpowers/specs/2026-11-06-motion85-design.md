# 브라우저 전투 모션과 상호작용 표현

사용자는 현재 모션 공백을 확인한 뒤 구현·검증을 반복하여 기존85점 목표까지 자동 진행하도록 요청했다. 기준은 main `4f647ef`, 독립 설계 평가84.625다. 기존 full-auto 및 원격 반영 권한을 적용한다. 이 문서의 구현 방식은 담당자의 판단이며 별도 사용자 선호를 추정하지 않는다. 점수 상승을 미리 보장하지 않는다.

## 선택한 접근

현재 실행·평가 대상인 브라우저 Canvas POC를 개선한다. (1) 기존 벡터 캐릭터와 상태 스냅샷 위에 표현 전용 타임라인을 얹으면 외형 조합·접근성·서버 권위를 유지할 수 있다. (2) 방향별 스프라이트 시트 교체는 자산 제작과 스킨별 중복이 크다. (3) Unity 전면 이식은 현재 브라우저의 기능/검증 경로를 바꾼다. 이번에는1을 선택한다. Unity C#/WebGL 완성을 주장하지 않는다.

## 보이는 변화

- 캐릭터: 확정된 인접 셀 사이 짧은 이동 보간, 네 방향 자세/얼굴, 걷는 발·팔·몸의 움직임. 멈추면 걷기를 마친다. 외형·팀·이름·본인 표시는 유지한다.
- 물폭탄: 설치 시 탄성, 퓨즈가 짧을수록 긴박한 흔들림, 폭발 중심의 물방울과 고리. 모든 스킨의 판정·기본 크기는 같다.
- 물줄기/블록: 서버가 확정한 모든 위험 셀은 즉시 보인다. 물결·거품·짧은 파편을 그 위에 추가하며 이펙트가 판정을 지연하거나 더 먼 곳이 위험한 것처럼 보이지 않게 한다.
- 피격/감금/구출/탈락/재합류: 짧은 충격, 감금 자세, 구출 고리, 구별 가능한 퇴장 잔상, 재합류 표시. 죽은 잔상은 살아 있는 선수의 표식을 갖지 않는다.
- 획득: 실제 획득 횟수 변화에만 반짝임·능력 종류 표시. 아이템 자체는 읽기 쉬운 기호를 유지한다.
- 다트/패스: 확정 경로는 즉시 표시하고 그 위에서 투사체를 짧게 이동시킨다. 실제 판정 시간은 바꾸지 않는다.
- 기존 full/calm/minimal·모션 줄이기·고대비를 유지한다. full에서만 이동 보간/몸 흔들림/움직이는 입자를 사용한다. calm 또는 모션 줄이기에서는 위치가 즉시 일치하고 필요한 짧은 정적 사건 표식만 남긴다. minimal은 장식 사건 효과를 생략하되 위험 셀·감금·팀·방향·문구를 보존한다. 화면 전체 섬광·카메라 흔들림·신규 강제 소리는 추가하지 않는다.

## 구조와 인터페이스

`Server/public/motion-timeline.js`는 DOM·Canvas·네트워크와 분리된 표현 상태를 소유한다. `createMotionTimeline()`은 `update(snapshot, {now, connection='connected', reducedMotion=false, effects='full', hidden=false})`와 `reset()`을 반환한다. 매 rAF의 now는 단조 증가 ms다. update는 현재 프레임 `{players: Map, orbs: Map, waves: Map, effects: Array}`를 반환하며 입력 스냅샷을 변경하지 않는다.

`players`의 ID별 pose는 `{player,x,y,facing,moving,walkPhase,walkWeight,bubble,hit,rescue,spawn,death,alpha}`다. x/y는 보간된 셀 좌표, player는 허용된 원본 선수 복사, hit/rescue/spawn/death는0..1 진행값 또는 비활성일 때 null, walkPhase는 라디안, walkWeight는0..1이다. 사망 잔상 alpha는 최대0.6이며 종료하면0. 새로운 명단에서 사라진 선수는 잔상을 만들지 않는다. `orbs`·`waves`는 `x,y` 문자열 키별 `{ageMs}`다.

pose.bubble은 boolean이다. effects.x/y도 셀 좌표이며 point에서 한 번만 변환한다. itemType을 확실히 알 수 없으면 일반 획득 표시를 쓰며 종류를 꾸미지 않는다.

effects의 원소는 `{id,kind,x,y,ageMs,durationMs,progress,playerId?,dx?,dy?,length?,interception?,itemType?}`이며 kind는 place/explode/break/pickup/hit/rescue/death/spawn/dart/pass다. 이동80ms, place160ms, explode450ms, break380ms, pickup600ms, hit200ms, rescue650ms, death420ms, spawn500ms, dart200ms, pass250ms를 기본값으로 한다. 플레이어 최대8·사건 최대128·타일별 기록 최대143로 제한하고, 만료를 매 프레임 정리한다. 독립 타이머나 입자별 Promise를 만들지 않는다.

baseline의 기존 orb/wave는 새 설치·폭발로 애니메이션하지 않도록 ageMs를 각각160/450 이상으로 시작한다. hit/rescue/spawn/death의 진행0도 활성 상태이며 null과 구별한다. 마지막 탈락과 함께 playing→finished가 된 snapshot은 해당 탈락 사건을 표시할 수 있으나, 새 경기·훈련 reset은 baseline이다. renderer.draw는 frame을 반환해 단위 검사가 실제 소비한 결과를 확인할 수 있다. 앱의 기존 호출은 반환값을 요구하지 않는다.

`visuals.js`의 기존 함수 호출은 호환한다. `drawAvatar(ctx, player, {time,reducedMotion,highContrast,pose})`에 선택적 pose를 추가한다. pose가 없으면 미리보기·결과 카드의 기존 정적 기본값을 유지한다. `drawOrb`는 선택적 ageMs, `drawPickup`은 선택적 time/reducedMotion을 받는다. 선수 위치 보간은 renderer만 적용하고 Avatar는 셀 내부 신체 모션을 담당한다.

`arena-renderer.js`는 타임라인을 소유하며 기존 draw(time,view)에서 frame을 얻는다. `arena-effects.js`의 `drawArenaEffects(ctx, effects, {point,highContrast,level,markerFont})`가 이미 투영된 사건을 그린다. point는 셀 좌표→Canvas 논리좌표 변환 함수다. 장식은 최대8개의 도형/입자씩, 결정적 분포를 사용한다. renderer는 본체·위험 셀·상태 표식을 사건 효과와 독립적으로 항상 그린다.

renderer는 visibilitySource(기본 document, 테스트에서는 주입 가능)의 visibilitychange 때 timeline.reset()을 호출한다. 숨겨진 탭에서는 rAF가 중단될 수 있으므로 draw의 hidden 검사만 의존하지 않는다. reset/dispose를 제공하고 dispose는 등록한 listener를 제거한다. snapshot 도착 시각은 rAF 시각과 구분하여 snapshot 객체가 새로 도착했을 때만 갱신한다.

app.js에는 renderer 생성 이후 별도 VM 구독으로 connection 변화 시 reset을 전달하고 기존 pagehide 경로에도 reset을 전달하는 최소 변경만 허용한다. connection이 프레임 사이에 끊겼다 회복돼도 과거 사건을 이어 재생하지 않게 한다. 초기화 순서/TDZ를 피하고 기존 입장·복귀 로직은 변경하지 않는다.

## 상태 경계

첫 접속·새 경기/맵/라운드·훈련 단계나 재시도 전환은 baseline이다. 구출/죽음/블록 파괴가 일어난 것처럼 재생하지 않는다. 연결 끊김·숨김·재개·300ms 초과 수신 공백·시계 역행·뒤로 간 서버 tick에서도 재기준화한다. 효과 수준 또는 움직임 줄이기 설정이 바뀔 때도 기존 사건을 지우고 orb/wave 나이를 안정 상태로 재기준화한다. 설정을 켜면서 이미 본 설치·피격 동작을 뒤늦게 재생하지 않는다. 같은 스냅샷을60fps로 반복해도 사건을 중복 생성하지 않는다. 같은 tick의 새로운 snapshot은 실제 값 변화만 한 번 처리한다.

인접한 한 칸의 확인된 이동만80ms 보간한다. 순간이동·재합류·두 칸 이상 변화는 즉시 맞춘다. 이전 보간 중 새 방향 이동을 받으면 이전 확정 셀에서 새 축을 시작하여 벽 모서리를 대각선으로 가로지르지 않는다. 서버 위치·충돌·폭발·쿨다운·점수·RPC·입력 전송은 변경하지 않는다. 렌더러는 읽기 전용으로 소비한다.

파괴는 soft 셀이 없어지면서 같은 셀에 실제 wave가 있을 때, 폭발은 사라진 orb 자리에서 wave가 확인될 때만 만든다. 감금 해제는 살아 있는 감금 선수가 정상 gameplay 중 풀린 경우만 구출로 표시한다. 훈련 reset이나 종료 화면으로 전환한 결과를 구출로 꾸미지 않는다. 획득은 itemsCollected 증가로 확인한다. 새로 보이는 다트/패스 경로나 TTL 재시작만 새 사건이며 기본 경로 표시는 snapshot과 일치한다.

## 확인할 증거

순수 타임라인에서 중간 위치·종착 위치·벽 모서리·수신 공백·복귀/재경기·중복 스냅샷·훈련 reset·이벤트 만료/상한·스냅샷 불변성·설정 전환을 검사한다. Canvas 검사는 실제 도형 좌표/스타일 차이와 고대비·방향·스킨·정적 카드 호환을 확인하고 소스 문자열을 정답으로 삼지 않는다.

실제 Chromium 입력으로 이동·설치·폭발/파괴·획득·피격/구출/탈락·다트·하모니 패스를 촬영한다. 게임 상태나 시계를 주입하지 않는다. full과 reduced/minimal, 모바일130%, 복귀·재경기 뒤 효과가 누적되지 않는 경로를 확인한다. 프레임 비용·효과 상한은 조건과 함께 기록하고 인터넷 서비스 수용량이나 실제 사람의 재미로 환산하지 않는다. 이전476개 전체 검사와 영향받는 브라우저 회귀를 실행하고 독립 코드 검토·같은20개 기준 Benchmark08 평가를 거친다. 서버 소스가 그대로면 이전SQL/서버 부하를 새로 실행한 것처럼 기록하지 않는다.

성공한 훈련은 같은 서버 tick 안에 다음 단계로 초기화되어 실제 중간 구출/아이템/다트 snapshot이 없어질 수 있다. 해당 모션의 실제 촬영은 정상 사람 대전/협동전에서 수행한다. 훈련 단계 초기화가 구출/죽음으로 오인되지 않는 것은 단위 검증한다.

다트 획득 촬영은 기존 `Server/test/fixtures/dart-drops.mjs`를 테스트 서버에만 preload하여 가능한 아이템 드롭을 결정적으로 만들 수 있다. 실제 블록 파괴→획득→다트 입력과 정상100ms 시간은 그대로 실행한다. 이 조건을 증거에 표시하며 운영 랜덤 분포나 무작위 실제 사용자 경기의 증거로 설명하지 않는다. 서버 상태/위치/판정/시계 직접 주입은 여전히 금지한다.

## 재평가 후 증분: 대상과 남은 퓨즈의 구분

첫 독립 잠정 평가는84.875였다. 실제 획득 프레임에서 캐릭터가 이동해도 표시가 수집 위치에 남는 공백을 확인했다. 다음 증분은 점수 보정 대신 이 혼동과 시간 정보의 부족을 보완한다.

- 선수 ID가 있는 획득·피격·구출·탈락·복귀 장식은 해당 선수의 현재 표시 위치에 연결한다. 폭발·파괴·설치는 발생 칸, 다트·패스는 확정 경로를 유지한다. 선수 이탈 시 표시를 제거하며, 이미 탈락한 선수의 과거 획득/구출 문구로 살아 있는 것처럼 보이게 하지 않는다. 타임라인 사건 원본과 서버 상태는 변경하지 않는다.
- 오브의20틱 기본 퓨즈를 읽는 고정 위치의 남은 비율 테두리를 모든3스킨과 효과 수준에 적용한다. 링의 남은 길이와 눈금이 색·흔들림 없이 시기를 구분한다. snapshot.fuse만 사용하고 로컬 시계로 차감하지 않는다. 연쇄 폭발은 더 일찍 일어날 수 있으며 이 표시는 안전시간 약속이 아니다. 위험 칸 표시는 계속 즉시 적용한다.
- 기존 캡처 원본을 보존하고, 실제 이동 중 획득·여러 폭탄/선수·구출의 새 장면을 기록한다. 수치·픽셀·프레임에서 대상과 시간 정보가 구분되는지 독립 평가한다. 인간 재미/판단 개선을 실측했다고 주장하지 않는다.
