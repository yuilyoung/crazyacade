# 친구와 시작하고 직접 배우는 4대4

기준 `874128e`, 2026-11-03. 사용자는 동일 벤치마크70점까지 자동 개선 후 원격 커밋을 요청했다. 숫자에 맞춰 평가 기준을 바꾸지 않는다. 구현·검증 뒤 독립 평가하고 부족하면 실제 공백을 추가 개선한다. 실제 이용자 재미/배포 완료와 설계 점수는 구분한다.

## 선택

새 전투 모드나 아트 확대보다 현재의 친구 모집·구출 학습·조작 장벽을 먼저 줄인다. 소규모 친구+AI 대전, 단계별 훈련, 조작/가독성/사건 안내를 하나의 첫 플레이 흐름으로 묶는다. 기존 Node/WebSocket·브라우저·봇을 재사용한다. 기존8인 클래식의 인증/랭킹/결과 큐와 모든 이전 기능을 유지한다.

## 친구+AI

- team join에 `humanSlots:2|4|6|8` 추가. 생략 시 기존 방 값 또는 새 방8, duel은2이며 team용 잘못된 값/충돌은 거부한다. practice는1. 사람 수는 재접속 예약도 포함한다. 정해진 사람이 모두 연결되면 남은 슬롯을 서버 AI로 채워 항상4대4로 시작한다.
- 2/4/6인 친구방은 인증을 그대로 요구하고 항상 비랭크다(`withBots:true`, `ranked:false`, resultSaving.unranked). demo/운영 랭킹과 outbox를 모두 우회한다. 8인 팀전과 duel의 기존 정책은 유지한다.
- AI 친구방만 `teamPreference:'auto'|'blue'|'pink'` 선택 가능. 한 팀4명 상한을 지키고 팀이 가득 차면 거부한다. 기본auto는 기존 교대 배정. 개인의 팀 선호는 초대 링크에 포함하지 않는다.
- 초대 링크는 기본 기존5필드 유지,2/4/6 팀방에만 `humans` 추가한다. 잘못된 query는8명으로 정규화. UI는 사람 정원·AI 수·비랭크와 팀 선택을 명확히 표시한다.
- 사람 정원이 차면 더 받지 않는다. 복귀/명시적 나가기/만료는 기존 계약. 재대결은 사람 전원 준비로 시작하고 봇은 새 라운드에 재구성한다. 사람 부족 시 충원을 기다린다. 마지막 사람이 나가거나 유예가 끝나면 봇만 남은 방을 정리한다. 봇 포함 공유방은 동시에16개 상한.

## 단계별 훈련

- `join {practice:true, training:true}` 전용. 일반방 training 요청은 거부하며 인증 우회로 사용하지 않는다. 훈련은 비공개 garden/team/itemMode=true/classic, 사람1명+정지 연습 대상7명. practice8방 제한/복귀 유예/결과 만료 정책을 공유한다.
- 서버가 단계·목표·실패·완료를 결정하고 클라이언트는 기존 input만 보낸다. 훈련 중 봇 AI와 일반 팀 전멸 판정은 사용하지 않으며180초 상한. 물폭탄/파동/피격/아이템/구출/다트는 실제 게임 로직을 따른다.
- 4단계: (1)물폭탄 설치 후 표시된 안전칸에서 폭발을 피함 (2)지정 상자를 폭파해 나온 파동 아이템을 실제 습득 (3)버블 아군 옆으로 이동해 구출 (4)멀리 있는 버블 아군을 다트로 구출. 서버는 훈련 상자의 아이템을 고정하고 단계마다 지형·위치·전투 상태를 준비한다.
- 대상은 구출 연습 중10초 버블 타이머. 죽거나 구출 제한시간을 놓치면1초 후 같은 단계를 재설정한다. 완료 단계와 실패 횟수를 표시한다. 카운터는 학습 결과를 보여주도록 유지하되 pending input·폭탄·파동을 새 단계에 넘기지 않는다. 네 단계 완료 시 training_complete, 제한시간은 training_timeout 비랭크 결과. 다시 훈련은 새 개인방/초기 단계.
- 공개 state.training은 null 또는 `{stage,step,total:4,title,instruction,target:{x,y},attempts,completed,status}`. stage는 escape/item/rescue/dart/complete, status는 active/retrying/complete. 초기화와 틱 진행은 독립 training.js에 두고 index.js는 호출만 연결한다. 실제 다트 구출은 fireDart 전후 rescues 변화로 기록한다.

## 조작·가독성·사건 안내

- 물리 `KeyboardEvent.code`를 사용해 한글 IME에서도 WASD가 작동한다. 이동4방향·폭탄·다트의 주 키6개를 바꿀 수 있고 방향키는 항상 별칭으로 유지한다. KeyA~Z,Digit0~9,Space만 배정; 중복/지원하지 않는 키는 거부. Ctrl/Alt/Meta·폼입력은 게임 조작으로 보내지 않는다. 설정 변경/blur/복귀는 held input을 비운다. 안내는 실제 설정 키를 표시한다.
- 왼손 터치 배치는 이동패드와 행동버튼 위치를 바꾼다. 기본 배치는 유지한다. 고대비는 명시적 CSS/캔버스 팔레트·굵은 외곽선·파동 해칭과 B/P 문자를 사용한다. 중요 작은 텍스트 대비4.5:1 이상을 검증한다. 전체 비시각 캔버스 플레이 지원으로 주장하지 않는다.
- 기본 키 복원, 고대비, 왼손 배치 설정을 localStorage에 저장하되 거부 시 메모리로 동작한다. 새 설정/자막/훈련 정보는 터치 조작 아래에 배치해390×844의 조작44px/화면 내 표시를 유지한다.
- 최근4~6개 주요 사건 자막: 내 아이템 변화, 버블 진입/구출/탈락, 팀 별 전달/결과. 매 틱이나 파동마다 읽지 않고 중복 제거한다. 무음으로 상황을 이해할 수 있도록 최신 문장만 live 안내하고 이름은 textContent로 처리한다. 새 경기에서 초기화하고 복귀 시 과거 사건을 쏟아내지 않는다.

## 검증과 평가

실제 WebSocket으로2/4/6명 충원·4대4 배정·팀 상한·인증·비랭크·재대결·복귀·마지막 사람 정리를 검사한다. 실제 Chromium으로 두 친구가 초대해 시작, 훈련 실패/4단계 완료/다시 시작, 한글key+물리code·키설정·고대비·왼손·무음 자막을 검증한다. 기존 전체/8인/릴레이/연습/재접속/저장/음향/DB/컨테이너 검사도 유지한다. 고정20하위 기준과 가중치는 그대로, 독립 평가자가70점 충족 여부를 판단한다.

## 독립 평가 뒤 보완

첫 구현의 독립 평가는68.75점이었다. 훈련 진입 발견, 단계 읽기 시간, 완료 후 연결과 모바일 사건 자막이 실제 화면의 공백으로 확인되어 다음을 추가한다. 점수는 다시 독립 평가한다.

- 첫 화면 위쪽에 `4단계 훈련`, `AI와 바로 연습`, `친구와 팀전`의 세 선택을 제공한다. 친구 선택은2인+AI 기본 설정으로 이동하되 자동 입장하지 않고 맵·팀·초대 설정을 확인하게 한다. 기존 세부 설정도 유지한다.
- 훈련의 각 단계와 실패 후 재도전은 `status:ready`에서 설명을 먼저 표시한다. `training_ready` 요청으로 본인이 시작한 뒤에만 전투 입력·구출 타이머를 처리한다. 이미 시작한 단계에 중복 요청을 보내도 재설정하지 않는다. 일반방에서는 무시한다. 전체180초 한도는 그대로 유지하므로 무한 점유는 없다. 읽는 동안 구출 대상의10초 타이머는 흐르지 않는다.
- ready 중에는 아레나 오버레이에 현재 설명과 `이 단계 시작` 버튼을 표시하고 키/터치 이동을 보내지 않는다. 모든 단계 전환과 복귀에서 held input을 비운다. 위쪽 기존 HUD 공간에도 현재 단계를 유지한다.
- 훈련 완료 화면에서 `AI 연습 이어하기`, `친구와 팀전 준비`를 제공한다. 전자는 선택한 캐릭터·맵을 유지해 일반 연습을 바로 시작하고, 후자는 개인방을 종료한 뒤2인 친구+AI 설정/초대 위치로 이동한다.
- 최근 사건의 한 문장을 아레나 아래 경계에 겹쳐 표시하여 모바일에서도 즉시 확인한다. 상세 기록은 기존 아래 목록에 유지하며 live 안내는 한 번만 한다. 방 변경/복귀 초기 상태에서 오래된 자막을 쏟아내지 않는다.
- 보완 재평가에서도69.75점으로70점 미만이었다. 390px 화면에서 캐릭터의 팀 문자·내 표시·버블 구출 시간이 너무 작다는 실제 공백이 남아 화면 크기에 맞춘 필수 표시를 추가한다. 팀은 원/B와 마름모/P로 색 외에 구분하고, 나·아군 구출·남은 초는 대비 배경과 읽을 수 있는 크기로 표시한다. 물감옥 상태에서도 긴 능력치 문구가 조작 버튼을 화면 밖으로 밀지 않도록 모바일 footer를 안정화한다. 실제 모바일 이미지와 피격 전후 버튼 위치를 다시 검증한다.
