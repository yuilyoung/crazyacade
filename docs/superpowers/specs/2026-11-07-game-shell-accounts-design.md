# 게임 화면·회원 경험 개선

사용자의 실제 Render 플레이 평가는 약30점이다. 기존85점에 가까운 점수는 구현 체크 중심의 설계 평가이며 실제 서비스 경험을 대표하지 못했다. 이번 변경의 성공은 점수 재상향이 아니라 다음 사용자 동작으로 확인한다.

## 목표와 흐름
- 시작/로그인 → 로비 → 캐릭터·스킨 → 맵·규칙 → 연결/대기 → 대전 → 결과를 각각 독립된 화면으로 제공한다.
- 대전 화면은 viewport 안에서 보드, 타이머, 아이템 상태, 나가기, 설정, 전체화면 및 터치 조작을 함께 유지한다. 페이지 전체를 스크롤해 게임을 찾는 구조를 없앤다.
- 회원가입/로그인/로그아웃, 세션 갱신, 내 프로필·전적·순위·결제내역을 Supabase와 연동한다. 결제는 사용자 확인에 따라 내역 구조만 구현하고 실제 청구는 PG 선택 후 진행한다.
- 인증/DB 오류와 빈 데이터는 구분한다. 설정 없는 공개 데모는 AI 연습·훈련을 제공하고 사람 대전은 인증을 요구한다.
- 이동은 서버 판정을 유지하면서 표현 보간의 멈춤/불연속을 줄인다. 위험 칸, 순간이동, 재접속, 움직임 줄이기 설정의 의미는 유지한다.

## 접근 선택
기존 Node.js+Canvas+Supabase를 유지하고 화면 상태 모듈을 도입한다. 새 프레임워크 재작성은 검증된 전투·입력·복구를 버리는 비용이 크고, CSS만 숨기는 방식은 화면 전환과 인증/대기 경계를 소유하지 못한다. 따라서 기존 DOM 요소와 컨트롤러를 화면별로 이동하고 명시적 화면 상태가 표시/포커스를 관리한다. 이 구현 선택은 자동 진행 범위에서 담당자가 결정했다.

## 경계
서버 JWT 검증·랭킹·경기 결과 집계는 유지한다. 회원 계정은 이메일/비밀번호와 새로고침 가능한 세션을 제공한다. 비밀번호/서비스역할키/카드번호를 게임 DB에 저장하지 않는다. 계정 조회·수정은 검증된 본인 ID만 사용하며 결제 기록은 클라이언트가 작성할 수 없다.

게임 로비는 플레이 방식, 캐릭터/맵 설정 요약, 랭킹·내 정보·설정 진입을 제공한다. 캐릭터와 맵은 별도 선택 화면이다. 입장 버튼은 연결 화면으로 전환하고 실제 서버 상태에 따라 대기/대전/결과로 이동한다. 일반 나가기는 로비로 돌아오며 재경기·복귀·훈련 이어하기는 기존 게임 연결 의미를 유지한다. 회원/랭킹의 긴 목록과 설정만 자체 패널에서 스크롤하고 대전 보드는 스크롤하지 않는다.

## 검증과 외부 설정
1440×900,1280×720,390×844,844×390에서 화면 격리, 실제 버튼→입장→대전, 전체화면 진입·ESC 복귀, 설정 열기·닫기, 터치 필수 버튼, 결과/재경기를 검사한다. 인증/프로필/내역은 실제 HTTP fixture와 격리 PostgreSQL로 검증한다. 운영 Supabase 키는 이 환경에 없으므로 실제 계정 활성화/마이그레이션/Render 환경값 적용과 공개 인터넷 검증을 별도 기록한다. 로컬 통과를 실제 서비스 완성이나 재미 점수로 바꾸지 않는다.
