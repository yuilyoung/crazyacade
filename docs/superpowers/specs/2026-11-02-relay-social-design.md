# 팝 릴레이와 친구 플레이 고도화

기준9bae5e3은 이미 커밋/푸시되었으며 사용자 요청은 다음 벤치마크 단계까지 고도화하고 커밋하는 것이다. 기존 자동진행 및 main 푸시 권한을 유지한다. 평가 항목과 가중치(완성도25/재미25/독창성20/접근성20/타깃10)는 바꾸지 않는다. 다음 설계점수는 구현·검증 후 재평가하며 목표 수치에 맞춰 올리지 않는다.

## 선택

기존 격자 전투에 아이템만 늘리면 독창성 공백이 남는다. 재접속/대규모 운영은 중요하지만 이번에는 즉시 경험 가능한 선택지인 **물폭탄·구출 + 별 운반의 팀 목적 모드**, 그리고 친구 합류/재대결을 함께 구현한다. 새 외부 서비스나 유료 API는 사용하지 않는다. Node.js 권위 서버, Canvas, 기존 BGM/접근성 선택을 유지한다. 핵심 전투 자체를 발명했다는 주장을 하지 않는다.

## 팝 릴레이

- `join.ruleSet`: `classic`(기본), `relay`. 잘못된 문자열/타입은 `invalid_rule_set`. 기존 방에서는 생략 시 방의 규칙을 따르고 명시 불일치는 `rule_set_mismatch`. relay는 team만 허용(`invalid_rule_mode`), practice는 원래대로team 강제.
- 중앙(6,5)의 별을 획득해 블루(1,5)/핑크(11,5) 기지에 가져오면 팀1점, 운반자 경기점수150점과 deliveries+1. 먼저3점 또는120초 뒤 높은 점수 팀 승리, 동점 무승부. 한 팀에 연결된 참가자가0명이면 남은 팀 기권승. 전원 생존 여부로 조기 종료하지 않는다.
- 별은 하나. 운반자가 버블/탈락/연결종료 시 현재 칸에 떨어진다. 같은 틱에 떨어진 별을 다시 습득하지 않도록1틱 보호. 득점 후5초 뒤 중앙 재생성. 서버만 운반/득점/복귀를 판정한다.
- 피격/버블2초/접근구출/다트/아이템은 기존 규칙을 따른다. 탈락하면5초 후 자신의 시작 지점으로 복귀하며1초 보호. 시작칸의 폭탄/파동 위험이 남아 있으면 복귀를 미뤄 안전한 시점에 반환한다. 업그레이드/경기점수/기존활성폭탄수는 유지하며 입력은 비운다.
- 릴레이의 중앙/기지 및 상하좌우 인접 칸은 파괴 블록만 제거해 목적물이 블록에 묻히지 않게 한다. 영구벽은 그대로다. 각 맵은 이 규칙으로 재생성한다.
- 릴레이는 연습과 사람대전 둘 다 제공하지만 비랭크: 모든 프로필/인증은 사람대전에 기존대로 적용하되 결과/레이팅 집계는 하지 않는다. 기존 클래식 랭킹은 유지한다.
- state: ruleSet, ranked(!practice && ruleSet===classic), matchId(진행/완료 경기UUID), relay={scores:{blue,pink},goal:3,star:{x,y}|null,carrierId|null,respawnTicks,bases:{blue:{x:1,y:5},pink:{x:11,y:5}} 또는null. players[]에 deliveries와 respawnTicks. result.reason, relayScores, scoreboard[].deliveries.
- 봇은 위험 회피와 아군 구조 후 별획득/운반을 시도한다. 봇 숙련도나 실사용자 재미를 검증했다고 주장하지 않는다.

## 친구 초대

선택 화면/방 안에서 초대 링크 생성. room,mode,map,items(1/0),rules를 포함하고 이름·토큰·키는 포함하지 않는다. 새 링크면 방 이름 자동생성. 상대는 링크로 같은 선택을 채우고 입장 버튼을 누른다(자동 입장 없음). URL은 현재 origin/path로만 생성하고 Clipboard 실패에도 읽기 전용 링크/복사 안내를 표시한다. AI연습방은 공유 불가. 파싱은 허용값 검증, 잘못된 값은 안전한 기본값 또는 명시 안내로 처리한다.

## 같은 방 재대결

일반방의 결과에서 `type:rematch`로 준비. 연결된 모든 사람이 준비하면 같은 소켓/플레이어ID/팀·외형/방설정을 유지해 새 라운드를 준비한다. 인원이 정원이면 즉시playing, 부족하면waiting에서 새 참가자 합류 가능. 새 matchId는 실제 시작 시 생성. 전투 맵/점수/아이템/입력/계수/결과/시간/릴레이/최종집계플래그를 모두 초기화한다. 이전 경기 저장용 snapshot은 손상하지 않는다. 준비 중 누가 떠나면 남은 인원의 준비를 다시 판단한다. 대기/경기 중 준비 메시지는 무시하고 중복투표는1회. 연습전은 기존처럼 새 개인방 즉시 시작.

state.rematch={readyPlayerIds:[],total}와 round(0부터, 새라운드 준비 때+1)를 제공한다. UI는 준비 수와 본인 준비를 표시하고, round 전환 시 안내/결과/입력/소리 장면을 초기화한다. 기존 사람대전의 다시준비 버튼은 이제 동일방 준비이며 나가기는 별도 유지한다.

## UI/검증

규칙선택 #rule-set, 릴레이목표 #relay-status(기존64px 알림슬롯 재사용), 초대버튼 #invite-button, 읽기전용링크 #invite-url, 안내 #invite-status. 중앙별·기지·운반자표식·복귀초·득점표시가 색 외 문자와 함께 보인다. 전달도 학습 안내에 표시한다. 모바일390x844에서 주요조작 가림/가로넘침을 방지한다. 기존 BGM/효과음 유지, 별획득/전달에는 기존item/rescue cue 재사용 가능.

서버단위/실제WS로 픽업·드롭·득점·복귀·승패·비랭크·방설정·다시준비 경계를 검증한다. 실제Chromium으로 초대URL→선택일치→입장,8인재대결,모바일릴레이와AI운반을 확인한다. 사용자 플레이테스트0명/공개배포미완료는 그대로 명시한다.
