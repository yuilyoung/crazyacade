# 연결 끊김 복구

2026-11-02. 기준 `ab6fdd7`. 사용자가 승인한 자동 고도화 범위에서 선택한 다음 작업이다. 기존 Node/WebSocket 서버와 브라우저를 확장한다.

## 목적과 선택

친구와 2분 경기를 하다가 일시적으로 연결이 끊기거나 새로고침해도 같은 참가자로 돌아온다. 즉시 탈락하는 현 구조, 계정만으로 임의 소켓을 교체하는 방식, 비공개 복귀 토큰과 계정 재검증을 조합하는 방식을 비교했다. 마지막 방식을 선택한다. 브라우저는 자동 복귀를 요청하며 기존 Unity/구형 클라이언트는 기존 즉시 이탈 동작을 유지한다.

## 계약

- `join.reconnect: true`인 사람에게만 `joined`에 32바이트 무작위 `resumeToken`, `reconnectGraceMs: 30000`을 보낸다. 토큰은 참가자 수명 동안 안정적으로 유지하고 공개 state, 로그, 초대 링크에 포함하지 않는다.
- `resume {roomId, playerId, resumeToken, accessToken}`은 기존 참가자/방을 찾고 토큰을 검증한다. 인증 입장자는 Supabase에서 같은 userId인지 다시 검증한다. 게스트/연습 복귀를 인증 실패의 대체 수단으로 사용하지 않는다. 정상 복귀는 `joined`에 `resumed:true`와 기존 정보, 이어서 최신 state를 보낸다. 복귀 중 profile/결과를 새로 쓰지 않는다.
- 활성 소켓이 아직 있으면 유효한 복귀가 이전 소켓을 교체한다(종료 코드4001). 이전 소켓의 입력/종료/지연된 인증 처리는 새 소켓에 영향을 주지 못한다. 잘못된 토큰/만료/사라진 방은 `resume_unavailable`, 계정 불일치는 `unauthorized`로 거부한다.
- 끊긴 참가자의 슬롯/팀/외형/위치/아이템/점수/경기 ID를 30초 보존한다. 입력은 비우고 경기는 계속되며 피격/물감옥/탈락이 계속 적용된다. 릴레이 별은 즉시 떨어지고 오프라인 참가자는 줍거나 전달하지 않는다. 봇 대체/추가 무적은 없다.
- state.players는 `connected`와 `reconnectRemainingMs`를 제공한다. 대기방은 전원이 연결되어야 시작한다. 종료방 재대결은 복귀 대기 인원을 포함해 전원 연결/준비가 필요하며 이탈/만료 시 재평가한다. 재연결은 준비 투표를 초기화한다.
- 명시적 `leave`는 즉시 자리와 복귀 권한을 제거한다. 브라우저의 나가기/새 연습전은 leave 후 종료한다. pagehide/새로고침은 leave를 보내지 않는다. 오프라인 나가기는 로컬 복귀 정보를 지우며 서버 자리는 유예 만료로 정리된다.
- 유예 만료는 기존 이탈/기권/결과/정리 규칙으로 처리한다. 연습방도 유예 중 유지하고 만료/명시적 이탈 때 정리한다. 정상 연습 결과의 기존 만료 정책은 유지한다.
- 서버는 ping/pong으로 조용히 끊긴 연결도 감지한다. 브라우저는 5초 ping, 12초 무응답 감지와 0.5/1/2/4초 상한 재시도로 복귀를 시도한다. 로컬 재시도 시간은 30초로 제한하고 서버의 만료 응답을 우선한다.
- sessionStorage에 현재 origin 전용 복귀 정보만 저장한다. 저장 실패 시 같은 페이지 자동 복귀는 가능하다. 새로고침은 config 로딩 뒤 저장된 참가자로 복귀한다. 복귀 중 화면/팀 명단은 유지하되 입력을 차단하고 상태·남은 시간·나가기를 제공한다. 만료/교체 시 명확한 안내와 로비로 복귀한다. 새 권한/서비스 키를 브라우저에 추가하지 않는다.

## 검증과 범위

실제 WebSocket 및 인증 fixture로 토큰 추측/계정 불일치/소켓 교체 경쟁/시간 만료/대기·경기·결과/재대결·연습·릴레이를 검증한다. Chromium으로 단절·새로고침·명시적 나가기·복귀 실패·모바일 화면을 확인하고 기존 클래식/릴레이/연습/음향을 회귀 검사한다. 실제 Supabase, 공개 배포, 서버 재시작/다중 인스턴스 사이 복구, Unity C# 복귀는 이번 범위 밖이다. 점수는 기술 근거가 늘어난 부분만 같은 기준으로 재평가한다.
