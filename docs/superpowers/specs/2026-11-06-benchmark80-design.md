# Pop Pop Arena: 조합하고 구하고 이어주는 팀 배틀

기준 b4fb258의 독립 설계 평가70점. 사용자 목표는 같은 기준80점이며 캐릭터/아이템/맵, 키보드/UI/설정/해상도, 창의성/캐주얼/마케팅을 개선하는 것이다. 이후 객체지향·MVVM 검토도 요청했다. 기존 full-auto 선호에 따라 구현 선택을 맡아 진행한다. 점수·인기도를 약속하거나 기준을 변경하지 않는다. 실제 참가자0명, 공개 운영/Unity 빌드 미검증이라는 한계는 유지한다.

## 선택과 범위

색상/메뉴만 늘리는 방안은 전략과 정체성의 공백을 해결하지 못한다. 프레임워크/Unity 전면 재작성은 현재 브라우저 POC와 검증을 버리는 비용이 크다. **현재 Node/브라우저를 유지하며 상태·표현·입력·규칙 경계를 추출하고, 실루엣이 다른 코스튬/구조가 다른 맵/패스와 구출이 득점을 바꾸는 하모니전/화면 설정을 연결**한다. 운영 인증·랭킹·복귀·저장 큐를 유지하고 새 모드는 비랭크로 시작한다.

## 구조

- `docs/Architecture/OOP-MVVM-Review-2026-11-06.md`의 현재 판정과 개선을 구분한다. JavaScript는 JSDoc 계약과 합성을 사용하며 private 필드/클로저로 소유 상태를 감춘다. 깊은 상속은 만들지 않는다.
- 브라우저에 DOM 없는 읽기 전용 `ArenaViewModel`을 둔다. authoritative state는 복제·동결하고 id/connection/settings에서 표시 모델과 명령 가능 여부를 만든다. ViewModel은 WebSocket/DOM/Canvas/AudioContext를 직접 생성하지 않는다. 소켓 포트와 뷰가 주입/구독한다. transport와 renderer를 app.js에서 추출하고 app는 조립/DOM 이벤트 연결을 담당한다. 입력 반복은 렌더 프레임과 분리한다.
- 서버는 중립 hazards 모듈과 규칙 전략 계약 `initialize/step/result/snapshot`을 사용한다. 룸/세션의 전면 교체는 하지 않으며 남는 공유 상태 결합은 문서에 명시한다. 랭크 정책은 공통 함수로 통일하고 Outbox 자체가 AI/연습/새 모드를 거부한다. 인증/프로필 어댑터는5초 시간 제한을 사용한다.

## 외형과 콘텐츠

- 캐릭터4종 유지. 기존 classic/sunset/mint와 새 astronaut/bee/raincoat의6코스튬: 모자 색 외에 의상·소품·무늬가 다르며 캐릭터 실루엣을 유지한다. 몸 색보다 원B/마름모P 표식으로 팀 식별을 보장한다. 능력치는 동일하다.
- 서버 검증 `orbSkinId: bubble|star|duck` 기본bubble. 폭탄 생성 시 소유자의 선택을 복사하여 공개 orb에 전송한다. 복귀/재대결에서 보존한다. 아이템 테마 `classic|candy|garden`은 브라우저 표시 설정이며 다섯 아이템의 의미·고대비 기호는 동일하다.
- `public/cosmetics.js`는 순수 카탈로그. `public/visuals.js`가 캐릭터/물폭탄/아이템을 그리며 로비 미리보기와 실제 경기에서 같은 함수를 사용한다. 모든 외형은 무료 선택이며 장식으로 전투 우위를 주지 않는다.
- 기존3맵과 가든 훈련의 배치를 유지한다. 새 `harbor`(썰물 부두: 길게 열린 교전로와 번갈아 열리는 수문), `festival`(풍선 광장: 순환 우회로와 중앙 합류)을 추가한다.13×11 좌우 대칭, 모든8출발점과 중앙/기지 연결, 출발칸과 인접칸은 안전하게 유지한다.
- `public/map-catalog.js`를 서버/미리보기 공통 배치 원천으로 사용한다. server state에 solid와 mapFeatures를 전송한다. 수문은10초마다 두 그룹의 개폐를 교대하며2초 전 예고. 닫힐 칸의 사람/봇/폭탄이 사라질 때까지 열린 상태로 기다린다. 사람을 밀거나 즉사시키지 않는다. 닫히는 칸의 아이템은 제거하며 봇·폭발·다트는 같은 최종solid를 사용한다. 훈련에는 수문이 없다.

## 패스·하모니

- `input.action=pass_star`와 기본G키/터치 버튼. 별 운반자가 바라보는 방향으로 최대7칸, 벽/상자/폭탄을 만나면 중단. 처음 만나는 생존·비버블·연결된 플레이어에게 전달한다. 적이면 가로채기다. 대상이 없으면 소유권을 유지한다. 같은 별의 성공 패스 간 대기10틱. 장식만 다른 발사 궤적/사건 피드백을 표시한다.
- 기존relay도 패스를 지원하지만 목표3점/전달1점 유지. 새 `harmony`는 team 전용 비랭크, 목표7점/120초/5초 복귀. 중앙 별을 전달할 때 기본1점+서로 다른 아군에게 성공 패스한 수(최대2)+별을 보유한 팀의 실제 구출 보너스(최대1), 최대4점. 같은 수신자 반복으로 중복 충전하지 않는다. 별을 떨어뜨리거나 상대가 가로채면 충전은0. 구출만 반복해 무한 득점할 수 없다.
- 봇도 같은 입력/패스 판정을 사용한다. 운반자는 기지 쪽의 연결된 아군에게 안전한 패스를 시도한다. 점수/charge/passEffect와 개인passes/interceptions를 공개하고 결과 기여를 보여 준다. 인증·인원·복귀·팀/아이템 정책을 동일 적용한다. 초대 rules=harmony를 왕복한다. 결과 저장과 임시랭킹에서 제외한다.

## 조작·화면·학습

- 물리 code별 held 상태를 보관한다. W+ArrowUp 중 하나를 놓아도 다른 키는 유지하고, 마지막 방향 해제 시 이전 방향으로 복귀한다. 폼/링크/설정/복귀/blur에서 게임 입력을 막고 비운다. 이동방식 연속/한칸, WASD/IJKL 프리셋을 제공한다. 새7번째 패스 키를 기존6키 설정에 충돌 없이 추가한다.
- 논리780×660과 실제 canvas 버퍼를 분리한다. 자동/절전/선명 품질과 DPR1/2, 최대1560×1320 버퍼. CSS비율/resize/방향 전환에서 맵이나 조작 판정은 바뀌지 않는다. 표식 계산은 논리 폭780을 사용한다.
- 집중 모드와 전체화면을 제공하고 Fullscreen API 거부/미지원은 집중 모드로 이어진다.390×844,360×640,844×390,1280×720,1920×1080에서 조작44px 이상·가로넘침 없음·캔버스 종횡비 유지. 가로 화면은 아레나와 조작을 좌우 배치한다. 긴 상태 문구로 버튼이 밀리지 않는다.
- 설정: 글자100/115/130%, 효과 full/calm/minimal, 사건 자막 표시, 아이템 테마, 렌더 품질, 집중모드·왼손·고대비·키설정·착장 선택 저장. 저장소 차단 시 메모리 동작. calm/minimal은 흔들림/빠른 맥동/과한 입자를 억제하고 소리도 편안한 프로필을 제공한다. 기본은 기존 음소거를 유지한다.
- Esc 설정 대화상자는 포커스를 잡고 닫을 때 돌려준다. 온라인은 경기 계속을 명시한다. 별도 서버 일시정지는 이번 초기 범위에서 제외한다. 새 모드는 실제패스·구출충전·전달의 상황별 안내를 제공한다.

## 공유·마케팅과 평가

- 실제 경기 결과의 본인 수치/구출·패스·전달/외형을 담은 카드 PNG 다운로드와 초대 링크 복사/사용자 클릭 공유를 제공한다. 개인 토큰·계정ID·서버키·다른사람 식별정보는 포함하지 않는다. 공유는 플레이어가 누를 때만 실행한다.
- 제품 소개/about와 OpenGraph 이미지/메타데이터, 조작·룰 설명, 공개 테스트 모집용 문안을 만든다. 광고 집행·외부 게시·가짜 인기/접속자 수·리뷰는 만들지 않는다. 인기도/리텐션/마케팅 성과는 미측정으로 분리하고 다음실험 KPI를 문서화한다.
- 고정20하위기준/가중치를 유지한 독립평가를 수행한다. 첫평가가80미만이면 실제공백을 우선순위로 보완하고 재검증한다. 자동검사를 사람의재미/인기도로 대체하지 않는다. 변경내용·검증·남은구조공백을커밋하고 기존사용자승인범위에서main에통합/푸시한다.

## 중간 평가 이후 실제 학습 공백 보완

첫 독립 잠정 평가는78.75였다. 기존 훈련은 클래식의 물폭탄·아이템·구출만 가르치므로, 하모니의 새 규칙을 실조작으로 익히는 별도 훈련을 추가한다. 목표 점수로 반올림하거나 기존 루브릭을 변경하지 않는다.

- private practice의 `training:true, trainingMode:'harmony'`만 새 훈련을 선택한다. 기존 기본 훈련은 그대로이며, 일반방·알 수 없는 trainingMode는 거부한다. Harmony 규칙과 안전한 festival 시나리오를 사용하고 전적/랭킹에는 저장하지 않는다.
- 단계는 실제 아군 패스→실제 가로채기로 충전 상실 확인→실제 버블 아군 구출 충전→충전된 별의 기지 전달이다. 단계 배치는 비공개 훈련이 준비하지만 성공·충전·점수는 공통 경기 엔진의 실제 행동 결과로만 결정한다. 이전 단계에서 실제 얻은 충전은 다음 연습에 전달할 수 있다.
- 설명 중 ready 상태는 전투·버블 타이머를 멈추고 전체3분 제한은 유지한다. 실패 시 같은 단계의 준비 상태로 되돌아가며 실패 이유를 표시한다. 입력으로 완료·충전 수치를 제출할 수 없다.
- 변경한 패스 키와 목표를 안내하고, 완료하면 선택해 두었던 맵·착장으로 하모니 AI 실전 또는 하모니 친구방 준비에 이어진다. 별도4단계 구조 훈련과 기존 전이 흐름을 유지한다.
- 실제 Chromium으로 성공·실패 재시도·읽기 대기·리맵 키·완료 후 전이를 확인한 다음 같은 평가자가 다시 평가한다. 특정 상승폭은 사전에 정하지 않는다.

2차 독립 평가는79.4375였다. 완료된 훈련은 실제 전달 점수·패스·구출·완료 단계를 요약하고 일반 경기의0:0/새 별1점 안내와 구분한다. 별 운반 중에는 현재 바라보는 방향으로 예상 패스 경로와 첫 수신자, 벽/상자/오브 막힘을 정적 표시한다. 아군✓·상대!·막힘×와 변경한 패스 키에 맞춘 짧은 안내를 함께 사용하고, 설정에서 끌 수 있다. 이 투영은 최신 공개 상태의 읽기 보조이며 서버 판정·명령 형식·수신자 권한을 바꾸지 않는다. 실제 작은 화면의 경로·가로채기 안내와 완료 요약을 재검증한다.
