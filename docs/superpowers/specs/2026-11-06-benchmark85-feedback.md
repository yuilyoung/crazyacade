# Benchmark85 증분: 파티 기여·목표 피드백·기다림과 읽기

기본 매칭/파티/운영 보강의 독립 잠정 평가는83.3125다. 목표85로 올림하지 않는다. 기존 full-auto 고도화 범위 안에서 실제 평가자가 지적한 사용자 경험 공백을 보완한다. 공개 배포·실제 인간 재미·새 콘텐츠 수를 허위로 점수화하지 않는다.

## 사용자에게 보이는 변화

1. 세 판을 마친 결과에서 **파티 전체 내 기여**를 본다. 첫 판의 구출이 마지막 판 개인기록0에 가려지지 않고, 판별 내 구출/패스/획득/전달과 합계를 구분한다. 완료 파티의 개인 공유 카드도 서버가 확인한 세 판 합계를 사용한다. 단판 카드와 현재 라운드 점수판은 유지한다.
2. 팀 협동 목표를 달성한 순간 한 번 **목표 달성·파티 보너스+1**을 알리고, 다음 행동을 안내한다. 모션/음향을 강제로 켜지 않으며 사건 자막·문자 단서를 사용한다. 과거 기록을 새 보너스로 재방송하거나 누적 점수를 클라이언트가 계산해 서버에 보내지 않는다.
3. 매칭은 최대3분,처음±100/15초마다50/최대±400 정책과 현재 다음 확대·남은 검색 시간을 표시한다. 실제 참여자 수·예상 대기시간을 만들어 표시하지 않는다. 취소/AI 연습은 명시적인 사용자 선택이다.
4. 기본/하모니 훈련의 설명 준비 중에는 전체3분 연습 시간도 보존한다. 서버의 실제 경기 틱은 계속 흐르고 훈련의 활동 시간만 별도 계산한다. 설명 무기한 점유를 막는 별도10분 idle 만료를 두며, 실제 단계 시작/진행 외 입력 스팸으로 연장하지 않는다. 일반120초 경기는 바꾸지 않는다.

## 데이터·계약

- `series.history[].contributions`는 그 판 roster의 실제 결과 카운터를 허용 목록으로 복사한다. `series.contributions`는 완료된 라운드만 합산하며 중복 finish에 증가하지 않는다. 새 파티에는 비운다. 필드는 공개 playerId/name/team/score/bombsPlaced/itemsCollected/rescues/passes/interceptions/deliveries이며 userId/JWT/socket/내부 참조는 없다. 최대3개 판·판당8명이다.
- 파티 전체 카드에는 본인의 합산 필드만 전달하며 다른 참가자의 이름·식별자·기여를 넣지 않는다. 서버의 현재 라운드 결과와 전체 파티 합계는 UI에서 명시적으로 구분한다.
- 목표 사건은 series ID/round/team으로 중복을 막는다. 처음 받은 이미 완료된 과거 파티나 복귀 baseline을 새 실시간 사건으로 오인하지 않는다. 실제 진행 중 target 도달을 관찰한 경우에만 발표한다.
- 큐 시간은 서버 elapsedMs/searchRadius에 근거하고 보여 주는 카운트다운은 음수가 되지 않는다. 만료 후 실제 서버 응답 없이 새 검색을 자동 시작하지 않는다.
- 훈련 idle 종료는 정상 승패·전적·랭크 저장을 만들지 않는 개인 훈련 결과이며, 읽기 준비를 다시 시작할 수 있는 설명을 제공한다. 종료 시 기존방정리·연습8방 상한을 보존한다.

## 소유권·검증

- series85: series 데이터/불변 투영/단위 테스트, party85 브라우저의 세 판 개인합계와 카드/목표 사건 확인.
- client85: UI/VM/사건 피드백/안전한 카드/매칭 정책·시간 표시, pure regression 및 매칭 브라우저.
- match85_impl: 훈련 활동 시간/idle 종료·server boundary tests, 실제 읽기/활동 시간 브라우저 증거를 client와 조율.
- root: 문서·통합·fullsuite·필요한 새/영향받은 브라우저 검증·최종 부하·독립 재검토/재평가·원격 반영.

이전424 tests, 기존회귀와 새8인 매칭·3판 파티 증거를 보존한다. 증분으로 바뀐 경계는 RED→GREEN 후 통합 검증한다. 점수는 실제 새 증거를 본 독립 평가자가 같은20개 기준으로 다시 판단한다.
