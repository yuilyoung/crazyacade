# 게임 표현·맵·아이템·일일 자동화 설계안

상태: 사용자 승인(진행해). 구현·로컬 검증 완료; 원격 활성화는 별도 확인 대상.

## 목적과 범위

기존 Node 권위형 서버와 Canvas 브라우저 게임을 확장한다. 물폭탄에 갇힘과 구출을 명확히 보여 주고, 이동의 자연스러움을 측정하며, 맵 선택과 실제 경기의 차이를 강화한다. 크레이지 아케이드의 격자 전투와 능력치 아이템을 참고하되 기존 독자 캐릭터·그래픽·합성 음원을 유지한다. Unity 및 운영 Supabase 변경은 포함하지 않는다.

## 접근 방법

권장안은 기존 표현 타임라인·공유 맵 정의·서버 아이템 판정을 확장하는 것이다. 서버 판정과 표시를 분리한 현재 구조를 유지할 수 있다. 렌더링 엔진 교체는 기존 접근성·입력·경기 회귀 범위를 크게 늘리므로 이번 범위에 맞지 않는다.

자동화는 기존 GitHub Actions 개선안 생성 및 격리 검증을 확장한다. 별도 클라우드 작업공간 예약 도구는 현재 제공되지 않는다. 작업공간의 임시 프로세스나 cron을 영구 스케줄러로 취급하지 않는다.

## 게임 변경

- 갇힘: 진입 시 탄성 압축, 갇힌 동안 작은 흔들림과 물방울, 탈출 시 터지는 링·파편·몸체 복귀. 기존 구출/탈락 판정을 따르고 핀 방어를 갇힘으로 표시하지 않는다.
- 이동: 확정된 격자 경로만 보간하며 코너를 가로지르지 않는다. 걸음 위상과 시작·정지 몸체 변형을 연속적으로 처리한다. 시각 효과가 충돌 판정을 바꾸지 않는다.
- 맵: 정원·라군·캔디·부두·광장 각각의 블록 색, 장식 오브젝트, 구조적 특징과 선택 설명을 일치시킨다. 장식은 실제 통행 불가 칸과 구별한다. 구조 변경은 양 팀 대칭, 시작점 안전, 모든 시작점 간 연결성을 검증한다.
- 아이템: 물폭탄 수·파동 범위·이동 속도의 서버 적용과 상한을 실제 이동/설치/폭발로 검증한다. 획득 표시에는 효과를 읽을 수 있는 설명을 제공한다. 외형만 커지고 판정은 바뀌지 않는 표현은 피한다.
- 음향: 다섯 맵의 템포·조성·악기 구성을 구별하고, 폭발·갇힘·탈출·벽 충돌·획득을 구분한다. 벽 충돌은 실제 거부된 이동 입력에서만 발생하고 반복 입력 시 제한한다. 기존 기본 음소거와 채널별 음량, 움직임 줄이기 설정을 유지한다.

## 90점 목표의 검증 방법

기존 문서의 85.125점은 AI 설계 평가이며 새 이동 품질의 측정값으로 사용하지 않는다. 구현 전에 재현 가능한 동일 이동 시나리오와 항목별 산식을 고정한다. 연속 직선·방향 전환·시작/정지·속도 아이템·수신 지연·움직임 줄이기에서 위치 연속성, 경로 준수, 몸체 위상 연속성, 입력 반응, 프레임 간격을 기록한다. 항목별 원자료와 실패를 공개하며 측정 후 90 미만이면 미달로 보고한다. 자동 시나리오 점수는 인간의 자연스러움 평가와 구분한다.

## 일일 자동화 제안

기본 시각은 매일 한국 시간 09:00(UTC 00:00). GitHub 예약 실행은 지연될 수 있다. 하루 한 번 제한된 개선안을 만들고 검증 실패 또는 변경 없음이면 반영하지 않는다. 기존 변경 경로 제한을 유지해 자격증명·워크플로·배포 설정·마이그레이션을 AI가 바꾸지 못하게 한다.

사용자 요청은 자동 수정 및 배포다. 권장 운영안은 검증한 변경을 기준 main SHA가 여전히 같을 때만 반영하고 Render의 checksPass 배포로 연결하는 것이다. 대안은 매일 검증된 초안 PR까지만 생성하는 것으로, 배포 전 사람의 병합이 필요하다. 현재 비동기 질문에서 선택 대기 중이다.

필요한 외부 설정은 GitHub Actions 활성화, 기존 AI API secret과 활성화 변수, 반영 방식에 맞는 최소 권한, Render 저장소 연결이다. 이 세션의 Git 읽기는 성공했지만 GitHub API는 Forbidden이므로 원격 secret 유무·예약 등록·배포 성공은 확인하지 못했다. 비밀값을 문서나 채팅에 저장하지 않는다.

## 검증과 현재 근거

### 구현자가 제안하는 고정 세부 기준

아이템 상한은 기존 폭탄 5개·범위 7칸·속도 1단계를 유지한다. 벽 충돌은 서버가 실제로 지형 때문에 이동을 거부한 경우만 증가시키는 공개 카운터로 표현하며, 쿨다운·갇힘·패킷 지연에는 증가시키지 않는다. 움직임 줄이기에서는 갇힘 흔들림과 탈출 파편을 정적 표식으로 대체한다.

맵별 구조물은 정원 화단, 라군 산호 기둥, 캔디 과자 벽, 부두 수문과 접안 기둥, 광장 풍선 기둥이다. 통행 불가 구조물은 solid 칸 안에만 그린다. 4대4의 대칭성과 우회로를 유지하고 1대1과 훈련의 기존 안전 배치를 별도로 검증한다.

이동 검증 점수는 총 100점으로 계산한다. 고정 60Hz 타임라인 시뮬레이션에서 위치 도약이 0.01칸 이하인 프레임 비율 25점, 진행 중 걸음 위상의 역행이 없는 프레임 비율 20점, 직선 이동 중 속도가 기준값 ±10% 이내인 프레임 비율 20점, 시작·정지 몸체 변화가 프레임당 0.1 이하인 프레임 비율 15점으로 각각 비율을 곱한다. 실제 Chromium의 단일 경기 10초 표본에서 rAF 간격 25ms 이하 비율에 20점을 곱한다. 직선·4회 방향 전환·시작/정지 각 10회·속도 아이템 전후·300ms 수신 공백 시나리오를 고정한다. 벽 관통 없음, 서버 확정 경로 준수, 움직임 줄이기 상태 정확성은 점수와 무관한 필수 조건이다. 측정 장치와 부하를 기록하며 90점 달성을 미리 주장하지 않는다.

일일 작업은 이 설계의 미완료 항목 한 개를 선택하고, 모두 끝나면 재현된 오류 한 개만 수정한다. 근거 있는 오류가 없으면 변경 없이 종료한다. 기존 보호 테스트의 삭제·약화는 허용하지 않고 원본 보호 검증과 새 검증을 함께 실행한다. GitHub 봇 토큰으로 반영한 푸시가 일반 CI를 유발한다고 가정하지 않는다. 반영 SHA를 대상으로 workflow_dispatch를 명시적으로 호출하고 해당 SHA의 CI 성공을 확인해야 하며, 그 후 Render에서 동일 SHA의 배포를 확인한다. 원격 인증과 연결이 확인되기 전에는 자동 배포 활성화 완료로 표시하지 않는다.

변경 전 npm ci는 /tmp 캐시로 성공했다. 기본 병렬 Node 테스트는 658개 중 657개 통과, 결과 저장 큐 용량 검사 1개 실패였다. 해당 파일 단독 재실행은 14/14, 전체 직렬 재실행은 658/658 통과했다. 실패 시점에는 실패 상태가 디스크 기록 완료보다 먼저 노출되어 임시 파일을 관측할 가능성이 있으나 병렬 실패의 원인은 아직 확정하지 않았다. 실제 Chromium 검사는 데스크톱·모바일 4개 해상도, 설정 유지·키 재설정, 두 종류의 훈련과 완료·재시작, 2인 재대결, 8인 4대4 실제 이동·물폭탄을 모두 통과했다. 새 게임 기능·90점·원격 자동화·실서비스 배포는 아직 검증하지 않았다.

구현 시 서버 테스트, 렌더러/타임라인/오디오 테스트, 실제 Chromium 이동·갇힘·탈출·획득 시나리오, 맵 선택과 경기 일치, 데스크톱/모바일과 접근성 회귀를 확인한다. 자동화는 스키마·변경 제한·검증 실패 시 미반영·기준 SHA 변경 시 중단을 테스트하고 원격 실행 결과를 별도로 확인한다.
